# P1：潮湿状态 Shader 完整设计解析

> 创建时间：2026-07-12 01:08  
> 适用项目：Unity 6.3、URP 17.3、Shader Graph  
> 阅读对象：第一次开发视角相关材质效果、正在学习 PBR 与实时渲染的开发者  
> 本文范围：只讲 Wet；完整解释 Smoothness、Fresnel、冷色 Tint、边缘水膜，以及它和 Burning、Gameplay 状态系统的组合方式。

---

## 一、先定义“潮湿看起来是什么”：它不是一层蓝色滤镜

潮湿状态在 Gameplay 中同样只是一个 0~100 的百分比，但视觉上不能简单理解为“角色变蓝”。如果只执行：

```text
FinalColor = Lerp(OriginalColor, Blue, WetIntensity)
```

角色会像中了冰冻或染色效果，而不是表面覆盖了一层水膜。潮湿更核心的视觉线索来自光如何在表面反射：水会填充部分微观凹陷，使有效表面更平整；从掠射角观察水膜时，反射也会更加明显。

因此当前 Wet 被拆成三个互补通道：

```text
1. Smoothness：提高光滑度，让高光更集中、环境反射更清晰。
2. Fresnel Edge：根据 Camera 视角增强轮廓水膜，提供视角相关反馈。
3. Subtle Tint：给正面区域非常轻微的冷色和变暗，弥补 Fresnel 在中央接近 0 的问题。
```

最终数据流是：

```text
Gameplay Wet（0~100）
    ↓ C# 归一化和平滑
Shader Wet Intensity（0~1）
    ├──→ Base Smoothness 向 Wet Smoothness 靠近
    ├──→ Burning 后的 Base Color 轻微冷色 Tint
    └──→ Fresnel × Edge Color 形成轮廓水膜
```

这三条线索各自解决不同问题。Smoothness 更接近材质物理变化，但依赖灯光和反射环境；Fresnel 在轮廓非常清晰，但角色正面区域几乎没有；Tint 在全表面可见，却容易被误认为纯染色。把三者以较低强度组合，才能在战斗镜头下既可读又不过度风格化。

## 二、常见实现方案与我们的取舍

最简单的方案是颜色 Tint。它成本低、几乎任何 Shader 都能做，但只改变颜色，不改变光照响应，容易像中毒、冰冻或阵营染色。

第二种是只提高 Smoothness。它利用 PBR 已有的高光与环境反射，材质逻辑比较合理，但如果场景缺少反射环境、Camera 较远或主光方向不合适，玩家可能很难看出状态。

第三种是 Wet Mask Texture。美术为模型绘制哪里会湿、哪里不会湿，控制精确，但角色和装备组合很多时需要大量资源；动态状态若要从局部向全身扩散，还需要额外 Mask 更新方案。

第四种是动态水滴 Normal、Flow Map 或 Screen-space Droplet。它能表现水流和雨滴，但需要更多纹理采样、UV 设计、时间动画，甚至需要 Render Feature；对于第一版全身状态反馈而言，成本和复杂度过高。

第五种是 Clear Coat 或双层 BRDF。物理上更接近“原材质表面覆盖一层介质”，可以单独计算底层与水膜反射，但当前 Shader Graph 的 Metallic Workflow 没有直接暴露完整水膜层控制；手写或扩展 Lit BRDF 会显著增加学习与维护范围。

第六种是透明、折射水层。把角色再绘制一遍透明壳可以表现水膜厚度与折射，但会增加 Draw Call、透明排序、Overdraw 和与动画 Mesh 同步的问题，不适合作为当前状态系统的基础版本。

最终选择是：

```text
保留 Opaque URP Lit
提高 Smoothness
使用 N·V 构造 Fresnel
用低强度冷色与浅蓝边缘做可读性补偿
不新增透明 Pass、不新增水滴贴图、不重写完整 BRDF
```

它不是完整物理水膜模拟，而是一种建立在 PBR 输入上的战斗状态近似。面试时不应把它包装成“真实水体渲染”，而应准确描述为：**用 Smoothness 表达微表面变平，用 Fresnel 近似掠射角反射，再用克制的 Tint 提高 Gameplay 可读性。**

## 三、为什么 Wet 必须和 Burning 写在同一个 Shader

项目的状态不是互斥枚举。角色可以同时：

```text
Burning = 0.6
Wet = 0.7
Poisoned = 0.3
Sticky = 0.2
```

如果每个状态创建一个 Shader，Renderer 的 Material 同一时刻只能选择其中一个，或者需要额外 Pass/Material。四种二元状态理论上就会产生 16 种组合，随着状态增加形成组合爆炸。

因此我们使用一个：

```text
SG_CharacterStatusLit
```

它保留原始 PBR，并拥有四个独立输入：

```text
_BurningIntensity
_WetIntensity
_PoisonedIntensity
_StickyIntensity
```

Neutral、Burning、Wet、Combined 四份 Lab Material 不是四个 Shader，只是同一 Shader 的四组参数，用于 A/B Comparison。

统一 Shader 中的颜色组合顺序是：

```text
Original Base Color
→ Burning 焦黑修改
→ Burned Base Color
→ Wet 整体 Tint
→ Wet Tinted Color
→ Wet Fresnel Edge
→ Final Base Color
```

这个顺序非常重要。Wet 必须从 `BurnedBaseColor` 开始，而不是重新从 OriginalBaseColor 开始，否则角色同时 Burning 与 Wet 时，Wet 分支会绕过或覆盖 Burning。可以把它理解成函数复合：

```text
FinalColor = ApplyWet(ApplyBurning(OriginalColor))
```

而不是：

```text
FinalColor = ApplyWet(OriginalColor) // 丢掉 Burning 结果
```

Wet 不修改 Burning Emission。焦黑表面可以变湿，但高温 Emission 是独立能量贡献；Gameplay 层会让 Wet 加速 Burning 衰减，随着 `_BurningIntensity` 降低，Emission 自然消失。Shader 不重复实现“水灭火”规则。

## 四、Smoothness：水膜怎样改变微表面反射

### 4.1 从宏观平面到 Microfacet

PBR 不把表面看成绝对平整的数学平面，而是把它近似成大量微小镜面的统计集合，即 Microfacet Model。宏观法线 N 描述整体朝向，但微观小平面可能围绕 N 分布。

粗糙表面的小平面方向很分散：同一束入射光被反射到较宽方向范围，所以高光宽、模糊、能量分散。光滑表面的小平面方向更集中：反射方向集中，高光更窄、更清晰，环境反射也更容易辨认。

Unity Material 给策划使用 `Smoothness`，值越高越光滑。很多 PBR 推导使用 `Roughness`；简化理解可以写成：

```text
PerceptualRoughness ≈ 1 - Smoothness
```

实际 URP 内部还会把感知粗糙度转换成用于 BRDF 的参数，并进行数值稳定处理，因此不要把上式误认为完整 URP 源码。但它足以建立方向感：Smoothness 上升，Roughness 下降。

水进入表面微小凹陷后，会让“空气-原材质”界面的一部分变成“空气-水膜-原材质”，有效表面反射通常显得更平整、更集中。当前方案用提高 Smoothness 近似这件事。

### 4.2 保留原材质差异

基础 Shader 已有：

```text
baseSmoothness
= Sample(_MetallicGlossMap,UV0).a × _Smoothness
```

贴图 Alpha 保留布料、皮肤、金属等区域的局部差异，Material `_Smoothness` 作为整体缩放。

错误做法是：

```text
finalSmoothness = WetIntensity
```

这会让所有区域在 Wet=0.5 时都变成 0.5，原本布料 0.2 与金属 0.9 的材质身份被抹平。

我们先计算：

```text
wetTargetSmoothness = max(baseSmoothness, _WetSmoothness)
```

Shader Graph 使用 `Maximum` 节点。`Max` 表示 Wet 只提高光滑度，不降低已有光滑度：

```text
布料：max(0.20,0.92)=0.92
金属：max(0.98,0.92)=0.98
```

如果直接把所有区域目标设为 0.92，原本 0.98 的金属反而会因潮湿变粗糙，违反设计意图。

最后使用：

```text
finalSmoothness
= lerp(baseSmoothness,wetTargetSmoothness,WetIntensity)
```

假设布料 Base=0.2、WetTarget=0.92：

```text
Wet=0.0 → 0.20
Wet=0.5 → 0.20×0.5 + 0.92×0.5 = 0.56
Wet=1.0 → 0.92
```

这让潮湿成为连续状态，而不是 Boolean 开关。`_WetSmoothness` 是 Material 美术参数，定义完全湿润时的目标；`_WetIntensity` 是代码实时参数，定义当前湿润程度。两个参数职责不同。

当前 Shader Graph 默认 `_WetSmoothness=0.92`，这是合理的初始值而非物理常数。调试时可临时设 1 证明链路，再回到 0.92 避免布料像玻璃。

## 五、Fresnel：为什么水膜在轮廓更明显

### 5.1 从点积理解视角

定义：

```text
N = Fragment 表面法线
V = Fragment 指向 Camera 的视线方向
```

两个单位向量的点积是：

```text
dot(N,V) = |N||V|cosθ = cosθ
```

正对 Camera 的表面，N 与 V 接近同向：

```text
θ≈0°，N·V≈1
```

球体轮廓附近，表面法线与视线接近垂直：

```text
θ≈90°，N·V≈0
```

所以：

```text
1 - saturate(N·V)
```

会得到中央接近 0、轮廓接近 1 的 Mask。

Shader Graph 中，我们创建 `Normal Vector(World)` 和 `View Direction(World)`，分别 Normalize 后进入 Dot Product，再经过 Saturate 和 One Minus。两个向量必须处在同一 Coordinate Space；如果一个是 Object Space、另一个是 World Space，数值看似都有 XYZ，几何意义却不成立。

`Normalize(v)=v/|v|` 把向量长度变成 1。如果不归一化，点积为 `|N||V|cosθ`，会把长度误差也混入角度结果。Shader Graph 的部分节点可能已经提供单位向量，但显式 Normalize 能让学习和数据契约更清楚。

`Saturate(x)=Clamp(x,0,1)` 用于限制插值误差或背面产生的越界值。`One Minus(x)=1-x` 则把“正面亮”反转成“轮廓亮”。

### 5.2 Power 如何控制边缘宽度

最终使用：

```text
wetFresnel
= pow(1-saturate(dot(normalize(Nws),normalize(Vws))),_WetFresnelPower)
```

Power 越大，中间值被压得越低，只保留接近 1 的轮廓：

```text
0.5^1 = 0.5
0.5^2 = 0.25
0.5^4 = 0.0625
0.5^8 = 0.0039
```

所以 `_WetFresnelPower` 控制形状宽度，不应拿它当亮度旋钮。当前默认值是 4，Slider 范围 0.5~8。

### 5.3 与物理 Fresnel 的关系

真实 Fresnel 反射表示不同观察角度下反射比例变化。实时 PBR 常用 Schlick 近似：

```text
F(θ) = F0 + (1-F0)(1-cosθ)^5
```

其中 `F0` 是正视角基础反射率。对于空气到水，折射率大约 `n1=1、n2=1.33`，正视角反射率近似：

```text
F0 = ((n1-n2)/(n1+n2))²
   ≈ ((1-1.33)/(1+1.33))²
   ≈ 0.02
```

也就是说，水正面仍有约 2% 基础反射，掠射角反射快速增强。

我们当前使用 `pow(1-N·V,Power)`，再乘浅蓝 Edge Color，是一个可调的风格化 Mask，不是完整 Schlick BRDF。它没有严格加入 F0、能量守恒、折射率和双层介质。选择它是为了第一次图形开发中把 Normal、View Direction、Dot Product、Coordinate Space 和 Power 建立起来，同时满足战斗可读性。

当前 `Normal Vector(World)` 使用几何法线，不直接使用 Base Normal Map 扰动后的结果。这样角色轮廓水膜更稳定，不会因衣服细碎 Normal Map 形成破碎边缘。代价是水膜不响应微观法线细节；后续可手动把 Tangent-space Normal 变换到 World Space再比较效果。

Fresnel 由 N 与 V 决定，所以应当随着 Camera 移动，而不是随着 Directional Light 移动。Debug 时如果旋转灯光导致你误判 Fresnel 位置，要把 Camera 和 Light 的变量分开测试。

## 六、从 Fresnel Mask 到冷色水膜：Tint、Edge 与组合顺序

### 6.1 Fresnel Edge

Fresnel 本身只是 0~1 标量。我们计算：

```text
wetEdgeMask
= wetFresnel × WetIntensity × _WetEdgeStrength

wetEdgeContribution
= _WetEdgeColor.rgb × wetEdgeMask
```

`_WetEdgeStrength` 当前默认 0.12，范围 0~0.3。范围故意较小，因为该分支只做轮廓提示，不应退化成卡通蓝色描边。

Edge Color 使用普通 Color，而不是 HDR，不进入 Emission。水膜表示反射增强，不应该在没有光照的黑暗中自己发蓝光。当前默认约为 `(0.62,0.87,1)`，Lab 调试曾提高到约 `(0.49,0.79,1)` 搭配更高 Strength。

最终当前方案使用风格化加法：

```text
colorWithEdge = wetTintedColor + wetEdgeContribution
```

这不是严格物理能量守恒的 Fresnel 反射。更物理的做法应该让 Fresnel 调制 Specular/Clear Coat，并相应减少透射或漫反射能量。当前 Metallic Lit Graph 没有直接暴露完整双层 BRDF，所以用低强度 Base Color Contribution 近似，换取实现清晰与 Gameplay 可读性。

### 6.2 整体 Tint

Fresnel 在正面中央接近 0，只靠轮廓不足以让玩家稳定识别 Wet。于是增加非常轻微的冷色 Tint：

```text
wetTintTarget = burnedBaseColor × _WetTintColor.rgb
wetTintAmount = WetIntensity × _WetTintStrength
wetTintedColor = lerp(burnedBaseColor,wetTintTarget,wetTintAmount)
```

当前默认 `_WetTintColor≈(0.75,0.90,1)`。乘法让红色通道衰减多、蓝色通道保留多，所以相对上变冷，并产生轻微变暗。例如：

```text
Input = (0.8,0.6,0.4)
Tint  = (0.75,0.90,1.00)
Target= (0.60,0.54,0.40)
```

Tint Strength 默认只有 0.08，因此完全 Wet 时也只向目标移动 8%。它是辅助信号，不应压过 Smoothness 与 Fresnel。

### 6.3 为什么顺序是 Burning → Tint → Edge

完整 Base Color 为：

```text
burnedBaseColor = ApplyBurning(originalBaseColor)

wetTintTarget = burnedBaseColor×WetTintColor
wetTintedColor = lerp(
    burnedBaseColor,
    wetTintTarget,
    WetIntensity×WetTintStrength)

wetEdge = WetEdgeColor
    × wetFresnel
    × WetIntensity
    × WetEdgeStrength

finalBaseColor = wetTintedColor + wetEdge
```

先 Burning，是为了保留焦黑状态；再 Tint，是为了让燃烧后的表面也能变湿；最后 Edge，是为了让 Edge Strength 独立控制轮廓，不再被 Tint 二次压暗。

Wet 不进入 Emission，所以：

```text
finalEmission = originalEmission + burnEmission
```

仍保持原样。水对火的抑制发生在 Gameplay：`StatusController.Tick()` 检测 Burning 与 Wet 共存时，将 `_wetExtinguishBurningPerSecond` 加到 Burning 衰减速度。随着事件发布更低 Burning 强度，Shader 中 Burn Emission 自动减弱。这种设计避免在 GPU 上复制战斗规则。

## 七、架构位置、参数职责和 Unity 技术

Wet 与 Burning 使用同一条跨模块链：

```text
Game.Combat.StatusController
    ↓ StatusChangedEvent
Game.Rendering.StatusMaterialController
    ↓ MaterialPropertyBlock
SG_CharacterStatusLit
    ↓ URP Lit Surface
```

`StatusController` 维护 0~100 Wet 强度，负责自然衰减、移动速度效果和 Wet 加速 Burning 衰减。`StatusMaterialController` 将其 `Mathf.Clamp01(intensity×0.01)` 归一化，并用 `Mathf.MoveTowards` 平滑 `_current.y`，最后写入：

```csharp
Shader.PropertyToID("_WetIntensity")
MaterialPropertyBlock.SetFloat(WetId,current.y)
```

代码实时控制的只有：

```text
_WetIntensity
```

Material 保存视觉风格：

```text
_WetSmoothness
_WetFresnelPower
_WetEdgeColor
_WetEdgeStrength
_WetTintColor
_WetTintStrength
```

这样 Gameplay 只表达“多湿”，Material 决定“这个世界的湿润材质应该长什么样”。不同区域或角色理论上可以使用不同 Wet 风格，但仍遵守同一个强度协议。

涉及的 Shader Graph 节点及作用：

```text
Maximum：确保 Wet 只提高 Smoothness。
Lerp：按 WetIntensity 连续插值。
Normal Vector(World)：读取世界空间几何法线。
View Direction(World)：读取表面指向 Camera 的世界空间视线。
Normalize：消除向量长度，只保留方向。
Dot Product：计算 N·V，即夹角余弦。
Saturate：Clamp 到 0~1。
One Minus：把正面亮反转为轮廓亮。
Power：控制 Fresnel 边缘宽度。
Multiply：组合强度、颜色与 Mask。
Add：加入风格化边缘颜色贡献。
```

目前 Fresnel 是纯 Shader Graph 节点实现。下一阶段计划创建带中文教学注释的 `StatusFresnel.hlsl`，用 Custom Function 重写同一公式，并将节点版与 HLSL 版并排比较。文档必须如实区分：HLSL Custom Function 尚未接入当前生产 Graph，不能在面试中说成已经完成。

## 八、真实 Debug、当前资产审计与性能边界

第一个认知问题是“Wet 是否要重新建 Shader”。答案是否定的。状态可以共存，因此应在统一 Lit Shader 内组合；四份 Lab Material 只是参数对照，不是四个 Shader。这一澄清避免了未来状态组合爆炸。

第二个问题是 Wet 效果不明显。Smoothness 依赖灯光、Camera 和环境反射，Material Preview 与场景可能不同。正确 Debug 方法是先把 Wet Smoothness 临时设 1、Wet Intensity 设 1，旋转 Camera 与灯光证明链路，再恢复合理参数；不要一开始通过大幅蓝色 Tint 掩盖 Smoothness 问题。

第三个问题是 Fresnel 的观察变量。它由 N·V 决定，应该旋转 Camera；Directional Light 只影响 Lit 高光，不决定 Fresnel Mask。把 Camera 与 Light 分开测试，能定位是几何视角链还是光照环境链。

第四个问题是 Coordinate Space。Normal 与 View Direction 必须同时为 World Space，并 Normalize。若中央白、边缘黑，检查是否漏了 One Minus；若 Power 越大边缘反而变宽，检查 Power 的 Base/Exponent 是否接反。

第五个问题是 Wet 误接 Emission。Edge Color 必须是普通 Color 并进入 Base Color，不是 HDR Emission。否则角色在黑暗中仍出现蓝色自发光，更像魔法护盾而不是水膜。

第六个问题是关闭条件。WetIntensity=0 时必须同时满足：

```text
FinalSmoothness = BaseSmoothness
TintAmount = 0
WetEdgeMask = 0
Burning 结果保持不变
```

如果任一效果残留，应从最终输出逆向检查是否有属性绕过了 WetIntensity。

本次资产审计发现，实验材质目前还没有按名称归位：

```text
M_StatusLab_Neutral:
    WetIntensity = 0.843
    WetTintStrength = 0.3
    WetEdgeStrength = 0.208

M_StatusLab_Wet:
    WetIntensity = 0

M_StatusLab_Combined:
    BurningIntensity = 0.6
    WetIntensity = 0
```

Shader Graph 的 `_WetIntensity` 默认值也仍是 1。这些是调试时在 Neutral 上调参数留下的，不是正确 Lab 基线。正式继续前应整理为：

```text
Shader Graph 安全默认：
WetIntensity = 0

M_StatusLab_Neutral：
Burning = 0
Wet = 0

M_StatusLab_Burning：
Burning = 1
Wet = 0

M_StatusLab_Wet：
Burning = 0
Wet = 1

M_StatusLab_Combined：
Burning = 0.6
Wet = 0.7
```

调好的公共风格参数，例如 Wet Smoothness、Fresnel Power、Edge/Tint Color，可以复制到四份材质；只有状态强度不同。Neutral 必须真正代表无状态，否则 A/B Comparison 失去基准意义。

性能方面，Wet 没有新增 Texture Sample，主要增加 Maximum、Lerp、若干 Multiply/Add，以及每 Fragment 的 Normalize、Dot 和 Power。Power 相对简单乘加更昂贵，但总体仍需 GPU Profiler 实测。统一 Shader 意味着 Wet=0 时这部分计算可能仍存在；未来若大量角色成为瓶颈，可评估 Shader Keyword，但必须权衡 Variant 数量和多状态组合。

当前 Fresnel 使用几何法线，性能与稳定性较好，但无法表现水滴微观法线。Tint 与 Edge Add 也不是严格能量守恒。升级方向可以依次考虑：

```text
1. 用 HLSL Custom Function 固化 Fresnel 数据契约。
2. 使用 Normal Map 转换后的 World Normal 影响水膜细节。
3. 添加低成本动态 Droplet/Flow Normal。
4. 使用 Clear Coat 或自定义双层 BRDF。
5. 局部 Wet Mask、接触水体扩散或环境湿润系统。
```

升级应由画面需求与 Profiler 数据驱动，而不是因为技术听起来更高级。

## 九、模拟大厂面试 Q&A

**Q：你如何把潮湿状态做得不像简单染蓝？**

A：我把 Wet 拆成三个信号。首先提高 Smoothness，表达水膜填平微表面后高光更集中；其次用 `1-N·V` 的 Fresnel 近似掠射角水膜；最后只用很低强度的冷色 Tint 补充正面区域可读性。Tint 是辅助，主要质感仍来自 PBR 光照响应。

**Q：为什么 Wet 与 Burning 使用同一个 Shader？**

A：状态可以同时存在。若每个状态一个 Shader，会产生 Shader/Material 切换和组合爆炸。统一 Shader 用独立 Float 控制各状态，在一次 Fragment Surface 计算中按明确顺序组合，Gameplay 通过 MPB 为每个 Renderer提供不同强度。

**Q：为什么 Wet Smoothness 使用 Max？**

A：Wet 目标应当只让表面更光滑。`max(base,wetTarget)` 可以提高粗糙布料，但不把原本 Smoothness=0.98 的金属降到 0.92。随后再按 WetIntensity 从 Base Lerp 到 Target，保留原材质差异和连续状态。

**Q：解释你使用的 Fresnel 公式。**

A：我先把世界空间法线 N 与视线 V Normalize，计算 `N·V=cosθ`。正面接近 1、轮廓接近 0，所以 `1-saturate(N·V)` 得到边缘 Mask，再用 Power 控制宽度。它是风格化近似；物理 Schlick 公式是 `F=F0+(1-F0)(1-cosθ)^5`，当前方案没有完整介质层与能量守恒。

**Q：为什么 Normal 和 View Direction 必须同空间？**

A：点积只有在同一基底下才表示夹角。Object Space 的 XYZ 和 World Space 的 XYZ 使用不同坐标轴，直接点积没有几何意义。我把两者都设为 World，并显式 Normalize，保证结果只与夹角相关。

**Q：为什么不让 Wet Edge 进入 Emission？**

A：水膜是反射增强，不是能量源。进入 Emission 会让它在黑暗中自己发蓝，更像魔法效果。当前 Edge 作为低强度 Base Color 贡献，Smoothness 继续由 Lit 光照处理；更物理的升级方向是 Clear Coat/Specular，而不是 HDR Emission。

**Q：Wet 怎样扑灭 Burning？是在 Shader 里相减吗？**

A：不是。灭火是 Gameplay 规则，StatusController 检测 Wet 与 Burning 共存后增加 Burning 衰减速度，并发布新的强度。Shader 只显示两个最新值。这样视觉替换不会改变战斗逻辑，也避免 CPU/GPU 两套状态规则不一致。

**Q：当前方案有什么不物理的地方？**

A：Fresnel 使用可调 Power 而非完整 Schlick 与水的 IOR；Edge Color 通过加法进入 Base Color，没有严格能量守恒；Smoothness 是全局状态插值，没有局部水滴厚度与流动。它定位为战斗状态表现，而不是水体模拟，我明确保留 Clear Coat、动态法线和局部 Mask 的升级接口。

**Q：怎么验证不是只在 Material Preview 里看起来有效？**

A：用 Neutral/Wet/Combined 同场 A/B，在 Game View 中固定光照并移动 Camera，分别观察 Smoothness、Fresnel 和 Tint；Wet=0 做无状态回归，Burning+Wet 做组合回归。随后接真实 SkinnedMeshRenderer，并用 Frame Debugger 与 GPU Profiler检查 Pass、SRP Batcher、Draw Call 和成本。

## 十、模拟面试者完整讲解开发流程

潮湿效果的输入来自通用状态系统。Combat 的 StatusController 维护 0~100 Wet 强度，并负责自然衰减和 Wet 加速 Burning 衰减；它通过带 TargetId 的 StatusChangedEvent 发布状态。Rendering 的 StatusMaterialController 只读订阅，把强度归一化到 0~1，并用 MoveTowards 平滑，再通过 MaterialPropertyBlock 写入 `_WetIntensity`。这样 Gameplay 规则、表现桥和 GPU Shader 各自单向依赖。

我没有为 Wet 创建独立 Shader，而是在统一的 URP Lit 角色 Shader 中组合状态，因为角色可以同时 Burning、Wet、Poisoned 和 Sticky。原始 PBR 仍保留 Base Map、Normal、Metallic、Smoothness、AO 和 Emission。颜色顺序是先计算 Burning 焦色，再在其结果上做 Wet Tint，最后添加 Fresnel Edge；Wet 不覆盖 Burning Emission，灭火通过 Gameplay 强度下降自然反映。

Wet 的第一条视觉线索是 Smoothness。我从 MetallicSmoothness Map 的 Alpha 与 Material Smoothness 得到 BaseSmoothness，然后用 `max(baseSmoothness,wetSmoothness)` 计算目标，避免潮湿把原本非常光滑的金属变粗糙。最终按 WetIntensity Lerp，因此粗糙布料逐渐变光滑，同时保留原贴图区域差异。

第二条线索是 Fresnel。我使用 World Space Normal 和 View Direction，Normalize 后做 Dot Product。由于正面 N·V 接近 1、轮廓接近 0，使用 `pow(1-saturate(N·V),power)` 得到轮廓 Mask。Power 控制边缘宽度，WetIntensity 与 EdgeStrength 控制贡献。这个公式是 Schlick Fresnel 的风格化近似，不是完整物理水膜，我用它在学习成本和战斗可读性之间取平衡。

第三条线索是非常轻微的冷色 Tint。它将 Burning 后的 Base Color 乘浅蓝青色得到目标，再按 `WetIntensity×TintStrength` 小幅 Lerp；随后将普通非 HDR 的 Edge Color 乘 Fresnel Mask 加到 Base Color。Smoothness 负责主要材质变化，Fresnel 负责视角相关轮廓，Tint 只补足正面可读性。

开发中我重点区分了 Camera、Light 和 Material 三类变量。Smoothness 需要灯光与环境反射才能看清，Fresnel 应随 Camera 而不是 Directional Light 变化，Edge 不应进入 Emission。最后使用四份共享同一 Shader 的 Lab Material做 Neutral、Burning、Wet、Combined A/B，并要求所有状态强度在 Shader 默认值中为 0，避免调试参数污染新材质。

当前节点版 Wet 已完成，下一步是用带注释的 HLSL Custom Function 重写同一 Fresnel 公式，与节点版并排验证；之后接入 WizardPlayer 与 MagicEnemy 的多个 SkinnedMeshRenderer，最后用 Frame Debugger 和 Profiler量化统一 Shader 与 MPB 的成本。
