# 静态投射物与陨石术设计 Spec

创建时间：2026-07-04 16:25:52  
功能名：Static Projectile Spell / Meteor Spell / 静态投射物与陨石术  
阶段：设计规格，待用户 review 后进入 implementation plan  
范围：新增 Noita-like “静态投射物”法术类别，并实现第一种静态投射物法术“陨石术”。不处理玩家自伤，不做完整 Buff/Status 重构，不做复杂地面选区系统。

---

## 0. 一句话目标

新增一类法术：

```text
StaticProjectile / 静态投射物
```

它和普通 `Emit` 一样会“产出一个运行时效果”，也会消耗 `drawBudget`，也能被 `Modify` 修正影响，也能作为触发 payload 被释放。

但它和普通 `Emit` 的区别是：

```text
普通 Emit：从释放点沿发射方向飞出去。
静态投射物：没有主要发射方向，以当前释放点作为效果位置。
```

陨石术就是第一种静态投射物：

```text
在释放点显示落点提示
从空中生成陨石本体
陨石砸向释放点
落地生成爆炸
爆炸造成范围伤害
```

---

## 1. 玩家可见效果

### 1.1 单独释放陨石术

法杖：

```text
[陨石术]
```

效果：

```text
以当前释放点作为陨石落点。
地面先出现 NovaFireball_LandingSite。
随后 NovaFireball 从天上坠落。
落地后生成 NovaExplosion_Hit。
爆炸造成范围伤害。
```

由于本项目暂时不考虑玩家自伤，所以即使落在玩家附近，也先不对玩家造成伤害。

### 1.2 和触发类投射物联动

推荐玩法：

```text
[触发类火球] [陨石术]
```

运行链路：

```text
玩家发射触发类火球
-> 火球命中敌人或环境
-> ProjectileBase.Impacted 触发 payload
-> SpellCaster.RunCast(payload, hitPoint, hitDir, ...)
-> 陨石术把 hitPoint 当作释放点 / 落点
-> 地面出现 NovaFireball_LandingSite
-> NovaFireball 从天上砸向 hitPoint
-> NovaExplosion_Hit 爆炸
```

这就是静态投射物和触发投射物组合的核心价值：

```text
触发投射物负责把“释放点”带到远处。
静态投射物负责在那个释放点产生强力效果。
```

### 1.3 和多重射击联动

由于 `StaticProjectile` 属于“产出类法术”，它应该和 `Emit` 一样消耗投射物预算。

例如：

```text
[三重射击] [陨石术] [火球] [火球]
```

应产出：

```text
1 个陨石术
2 个火球
```

注意：`Modify` 不消耗投射物预算，`Emit` 和 `StaticProjectile` 消耗投射物预算。

## 2. 为什么要新增 StaticProjectile，而不是继续用 Emit

### 2.1 当前 `SpellKind` 的问题

现在 `SpellKind` 是：

```csharp
public enum SpellKind : byte
{
    Emit = 0,
    Modify = 1,
    Multicast = 2,
}
```

普通 `Emit` 的隐含语义是：

```text
从 spawnPos 沿 baseDir 发射 projectilePrefab。
```

但陨石术的语义是：

```text
spawnPos 不是发射起点，而是落点 / 释放点。
baseDir 不是主运动方向。
陨石本体需要从空中生成，再砸向 spawnPos。
```

如果硬塞进 `Emit`，`SpellCaster` 里会出现很多特殊判断：

```text
如果是火球 -> 直线发射
如果是陨石 -> 从天上落
如果以后是火环 -> 原地生成
如果以后是黑洞 -> 原地生成
```

这会让 `Emit` 概念变得不清楚。

### 2.2 推荐新增 `StaticProjectile`

推荐：

```csharp
public enum SpellKind : byte
{
    Emit = 0,
    Modify = 1,
    Multicast = 2,
    StaticProjectile = 3,
}
```

必须把 `StaticProjectile` 加在最后，不能插入到中间。

原因：

```text
Unity 会序列化 enum 的数字值。
已有资产中 Emit=0, Modify=1, Multicast=2。
如果把新值插到中间，会导致已有资产 Kind 错位。
```

### 2.3 概念新增，但不新增一套系统

虽然新增 `StaticProjectile` 法术类别，但不建议做一套完全独立的 `StaticSpellCaster`。

原因：

```text
静态投射物仍然是法术编程系统中的产出类法术。
它应该继续走 CastEvaluator。
它应该继续受 Modify 影响。
它应该继续能被 Multicast 计数。
它应该继续能作为 Trigger payload 被释放。
```

所以最终架构是：

```text
概念上新增 SpellKind.StaticProjectile
架构上复用 EmitCommand / SpellCaster / ProjectileBase / AreaDamage
```

## 3. 常见实现方案

### 3.1 方案 A：把陨石术做成普通 Emit 的特殊 prefab

做法：

```text
SpellKind 仍然是 Emit。
ProjectilePrefab 填 NovaFireball。
SpellCaster 仍然从 spawnPos 沿 baseDir 发射。
```

优点：

- 改动最少。

缺点：

- 不能表达“静态投射物”这个玩法分类。
- 陨石会像普通投射物一样从释放点发射，不符合需求。
- 后续所有静态法术都要继续挤进 Emit。

结论：

不采用。

### 3.2 方案 B：给 Emit 增加 `EmitPattern`

做法：

```text
SpellKind 仍然是 Emit。
SpellDefinition 增加 EmitPattern：
    ForwardProjectile
    SkyfallAtPoint
    StaticArea
```

优点：

- enum 不增加 `SpellKind`。
- 数据上可以区分发射模式。

缺点：

- 玩家和设计文档中“静态投射物”这个分类不够清晰。
- `Emit` 会同时代表“飞行投射物”和“原地效果”，概念边界变宽。

结论：

可行，但不如新增 `StaticProjectile` 清晰。

### 3.3 方案 C：新增 `StaticProjectile`，底层复用产出链路

做法：

```text
SpellKind 新增 StaticProjectile = 3。
CastEvaluator 把 Emit 和 StaticProjectile 都视为“产出类法术”。
EmitCommand 增加 SpawnMode 或 StaticProjectile 相关字段。
SpellCaster 根据 Command 的生成模式选择：
    ForwardProjectile
    SkyfallAtPoint
```

优点：

- 玩家语义清晰。
- 架构仍然复用现有解释器。
- 后续可以继续扩展火环、黑洞、地雷、领域等静态投射物。
- 面试表达更清楚：新增玩法分类，但没有复制系统。

缺点：

- 需要改 `SpellKind`、`CastEvaluator`、`SpellDefinition`、`EmitCommand`、`SpellCaster`。

结论：

采用。

## 4. 最终设计

### 4.1 新增法术类别

修改：

```text
Assets/_Project/Scripts/Skills/SpellKind.cs
```

新增：

```csharp
StaticProjectile = 3
```

语义：

```text
StaticProjectile 是产出类法术。
它消耗 drawBudget。
它会生成运行时效果。
它受前置 Modify 影响。
它可以作为 payload 被触发释放。
```

### 4.2 新增静态投射物生成模式

推荐新增一个更底层的生成模式 enum：

```csharp
public enum SpellSpawnMode : byte
{
    ForwardProjectile = 0,
    SkyfallAtPoint = 1,
}
```

解释：

```text
SpellKind 解决“这是哪类法术”
SpellSpawnMode 解决“这个产出类法术如何生成运行时对象”
```

普通火球：

```text
Kind = Emit
SpawnMode = ForwardProjectile
```

陨石术：

```text
Kind = StaticProjectile
SpawnMode = SkyfallAtPoint
```

### 4.3 `SpellDefinition` 新增字段

在 `SpellDefinition` 中新增静态投射物相关字段：

```csharp
public SpellSpawnMode SpawnMode = SpellSpawnMode.ForwardProjectile;
public GameObject LandingSitePrefab;
public GameObject ImpactVfxPrefab;
public float SkyfallHeight = 12f;
public float SkyfallBackOffset = 0f;
public float LandingSiteDuration = 0.8f;
public float ExplosionRadius = 3f;
```

字段含义：

| 字段 | 作用 |
|---|---|
| `SpawnMode` | 本产出法术如何生成运行时对象 |
| `LandingSitePrefab` | 落点提示，如 `NovaFireball_LandingSite` |
| `ImpactVfxPrefab` | 落地爆炸特效，如 `NovaExplosion_Hit` |
| `SkyfallHeight` | 陨石从落点上方多高生成 |
| `SkyfallBackOffset` | 是否沿反方向后撤一点形成斜砸效果 |
| `LandingSiteDuration` | 地面提示提前显示多久 |
| `ExplosionRadius` | 落地范围伤害半径 |

本阶段可以先让陨石几乎垂直落下：

```text
SkyfallBackOffset = 0
```

这样实现更稳定。

### 4.4 `EmitCommand` 新增字段

`EmitCommand` 需要快照静态投射物参数：

```csharp
public readonly SpellSpawnMode SpawnMode;
public readonly GameObject LandingSitePrefab;
public readonly GameObject ImpactVfxPrefab;
public readonly float SkyfallHeight;
public readonly float SkyfallBackOffset;
public readonly float LandingSiteDuration;
public readonly float ExplosionRadius;
```

原因：

```text
运行时不能再回头查 SpellDefinition。
CastEvaluator 应把本次施法所需参数快照进 EmitCommand。
```

### 4.5 `CastEvaluator` 解释规则

`CastEvaluator` 需要把 `Emit` 和 `StaticProjectile` 都视为产出类法术：

```text
case SpellKind.Emit:
case SpellKind.StaticProjectile:
    如果 drawBudget <= 0 -> 不产出
    检查 mana
    BakeEmit(...)
    drawBudget--
```

注意：

```text
Modify 不消耗 drawBudget。
Multicast 增加 drawBudget。
Emit / StaticProjectile 消耗 drawBudget。
```

### 4.6 `SpellCaster` 生成规则

`SpellCaster` 根据 `EmitCommand.SpawnMode` 分流：

```text
ForwardProjectile:
    从 spawnPos 沿 baseDir 发射

SkyfallAtPoint:
    把 spawnPos 当作落点
    生成 LandingSitePrefab
    在落点上方生成 NovaFireball
    让 NovaFireball 朝落点飞
```

伪代码：

```csharp
switch (cmd.SpawnMode)
{
    case SpellSpawnMode.ForwardProjectile:
        SpawnForwardProjectile(cmd, spawnPos, baseDir, ...);
        break;

    case SpellSpawnMode.SkyfallAtPoint:
        SpawnSkyfallProjectile(cmd, spawnPos, baseDir, ...);
        break;
}
```

### 4.7 陨石落点如何确定

陨石术的落点就是 `RunCast` 传入的 `spawnPos`。

直接施放：

```text
spawnPos = 法师施法点
```

触发释放：

```text
spawnPos = 触发火球命中点 hitPoint
```

这正好符合玩法：

```text
没有联动 -> 陨石落在玩家附近
触发联动 -> 陨石落在目标处
```

### 4.8 陨石爆炸如何处理

有两种实现：

#### 方案 1：让 `NovaFireball` 自己负责爆炸

要求：

```text
NovaFireball prefab 上的 ProjectileBase 派生脚本在 OnImpact 中生成 NovaExplosion_Hit。
```

优点：

- 爆炸逻辑跟随 projectile prefab。
- SpellCaster 不需要知道陨石落地后怎么爆炸。

缺点：

- 如果 `NovaFireball` 当前没有对应脚本，需要补一个 `MeteorProjectile` / 配置字段。

#### 方案 2：SpellCaster 给陨石配置落地爆炸 prefab

要求：

```text
ProjectileBase 支持 ConfigureImpactVfx(GameObject prefab, float radius)
```

优点：

- 数据驱动，陨石术资产里可以填 `NovaExplosion_Hit`。

缺点：

- `ProjectileBase` 会继续变胖。

推荐本阶段：

```text
使用项目现有 NovaFireball。
NovaFireball 已经是 ProjectileBase 派生类，并且 OnImpact 已经负责生成 NovaExplosion_Hit / FireField。
```

原因：

```text
陨石的落地爆炸是该 projectile 的表现和伤害逻辑，现有 NovaFireball 已经承担这部分职责。
SpellCaster 本次只负责 SkyfallAtPoint 生成方式和落点提示。
```

## 6. 与现有系统的集成

### 6.1 与触发类投射物

组合：

```text
[触发火球] [陨石术]
```

链路：

```text
触发火球命中
-> ProjectileBase.Impacted
-> SpellCaster.RunCast(payload, hitPoint, hitDir, ...)
-> 陨石术以 hitPoint 为落点
```

这是本功能最重要的玩法场景。

### 6.2 与多重射击

组合：

```text
[三重射击] [陨石术] [火球] [火球]
```

语义：

```text
StaticProjectile 和 Emit 一样消耗投射物预算。
```

因此会产出：

```text
1 个陨石
2 个火球
```

### 6.3 与修正法术

静态投射物应该受通用修正影响：

| 修正 | 对陨石术的预期 |
|---|---|
| 增伤 | 增加爆炸伤害 |
| 加速 | 增加陨石下落速度 |
| 多重 | 允许一次产生多个静态投射物 |
| 追踪 | 本阶段不建议影响陨石 |
| 轨道 | 本阶段不建议影响陨石 |
| 重力 | 对陨石本体可以无效，因为陨石由 Skyfall 速度控制 |
| 弹跳 | 对陨石本体可以无效或不推荐组合 |

注意：

```text
这是第一个静态投射物，所以不需要一次性解决所有修正组合。
但 spec 必须明确哪些修正本阶段生效，哪些先忽略。
```

### 6.4 与运动控制修正的冲突

陨石术本身是 `SkyfallAtPoint`，它的主运动语义是：

```text
从天上向落点坠落。
```

因此它天然带有一种“运动模式”。

本阶段建议规则：

```text
StaticProjectile / SkyfallAtPoint 优先使用自己的生成与运动模式。
Homing / Orbit 这类后续运动控制修正暂不影响陨石。
```

原因：

```text
如果陨石又追踪、又轨道、又从天上落，语义会混乱。
本阶段陨石术先保持清晰：落点固定，陨石坠落。
```

后续如果要支持“追踪陨石”，更合理的设计是：

```text
落点提示期间落点跟随目标移动
```

而不是让陨石本体飞行中 homing。

### 7.1 EditMode tests

需要覆盖：

1. `SpellKind.StaticProjectile` 不改变已有 enum 值：

```text
Emit = 0
Modify = 1

StaticProjectile = 3
```

```text
baseDraws = 1
```


```text
[触发火球] [陨石术]
```

## 8. Debug 关注点

### 8.1 陨石落在玩家脚下

这是正常现象。

原因：

```text
静态投射物没有发射方向。
直接释放时 spawnPos 就是玩家施法点附近。
```

推荐玩法是：

```text
[触发火球] [陨石术]
```

### 8.2 陨石没有在命中点释放

排查链路：

```text
触发火球 PayloadTrigger 是否为 OnImpact
CastEvaluator 是否捕获了陨石术作为 payload
ProjectileBase.Impacted 是否触发
SpellCaster.RunCast(payload, hitPoint, hitDir, ...) 是否把 hitPoint 传给 StaticProjectile
```

### 8.3 地面提示不显示

排查：

```text
LandingSitePrefab 是否配置
生成位置是否在地面以下或太高
LandingSiteDuration 是否太短
Prefab 是否有可见 Renderer/VFX
```

### 8.4 陨石不爆炸

排查：

```text
NovaFireball 是否有 ProjectileBase / MeteorProjectile
落地是否产生 Collision
NovaExplosion_Hit 是否配置
OnImpact 是否实例化爆炸
AreaDamage 是否配置攻击方 team / attackerId
```

### 8.5 陨石穿过地面

排查：

```text
Rigidbody.collisionDetectionMode 是否 ContinuousDynamic
Collider 是否启用
地面是否有 Collider
速度是否过大
```

## 9. 成功标准

功能完成后应满足：

1. `SpellKind` 新增 `StaticProjectile = 3`，不破坏已有资产。
2. `StaticProjectile` 被 `CastEvaluator` 视为产出类法术。
3. `StaticProjectile` 消耗投射物预算，能被 `Multicast` 扩展数量。
4. 陨石术直接释放时落在释放点。
5. `[触发火球] [陨石术]` 时，陨石落在触发命中点。
6. `NovaFireball_LandingSite` 作为落点提示出现。
7. `NovaFireball` 从天上坠落。
8. `NovaExplosion_Hit` 在落地处生成。
9. 爆炸能对敌人造成范围伤害。
10. 本阶段不处理玩家自伤。

## 10. 面试表达点

可以这样讲：

> 我在法术编程系统里新增了 Noita-like 的 `StaticProjectile` 法术类别。它和普通 `Emit` 一样属于产出类法术，会消耗投射物预算、能被 `Multicast` 计数、也能受前置 `Modify` 影响。但它和普通 `Emit` 的区别是：普通 `Emit` 依赖发射方向，而 `StaticProjectile` 以当前释放点作为效果位置。

继续：

> 陨石术就是第一种静态投射物。直接释放时，它会在玩家释放点召唤陨石；和触发火球组合时，触发火球的命中点会作为陨石落点。这个设计复用了现有 `CastEvaluator -> EmitCommand -> SpellCaster` 链路，而不是为陨石术单独写一套系统。这样后续火环、黑洞、地雷等静态投射物都可以沿同一套机制扩展。
