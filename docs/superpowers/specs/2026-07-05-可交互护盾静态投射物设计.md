# 可交互护盾法术设计（修正版：Emit 型护盾投射物）

创建时间：2026-07-05  
修正说明：本文件替换上一版“可交互护盾静态投射物”方案。上一版把移动护盾设计成 `StaticProjectile + StaticAtPoint + Rigidbody`，语义不准确；本版改为 `Emit + ForwardProjectile`。

## 1. 问题复盘

上一版方案的目标是让护盾具备物理交互：可以被投射物推动，也可以被重力、弹跳、追踪、轨道等修正影响。为了不把护盾放进 `ProjectileBase` 的伤害命中流程，我设计了 `SpellPhysicsBody`，让静态投射物也能接收运动修正。

但经过实际思考和测试，这个方向有两个问题：

1. **玩法语义不对。**  
   用户想要的效果是“护盾像投射物一样从法杖发射出去”。这不是静态投射物，而是一个具有护盾能力的发射物。它应该属于 `SpellKind.Emit`，使用 `SpellSpawnMode.ForwardProjectile`。

2. **物理表现容易出错。**  
   如果静态护盾生成后直接带 `Rigidbody` 并受重力影响，而 prefab 的实体 Collider / Layer Collision Matrix 没配好，它会穿过地面。即使修好地面碰撞，它也仍然是“点位生成物”，而不是“从法杖发射出去的护盾投射物”。

因此本功能应改为：

```text
新护盾法术 = Emit 型护盾投射物
旧护盾术 = StaticProjectile 原地护盾场
```

旧护盾保留，新护盾作为一个新的 `Emit` 法术实现。

## 2. 功能目标

新增一个“护盾投射物”法术。玩家释放后，护盾像火球一样从法杖方向射出，在飞行过程中具备护盾反弹能力。

玩家可见效果：

1. 护盾从玩家施法点沿瞄准方向飞出去。
2. 护盾飞行过程中可以反弹进入范围的玩家或敌方投射物。
3. 反弹敌方投射物后，敌方投射物改为护盾释放者阵营，可以伤害敌人。
4. 护盾本体可以被重力、弹跳、追踪、轨道等 Modify 法术修正。
5. 护盾可以参与 Multicast，例如三重射击发射三个护盾。
6. 护盾可以被 Trigger payload 释放，例如：

```text
触发火球 -> 护盾投射物
```

火球命中后，护盾从命中点沿触发方向继续发射，而不是原地生成。

## 3. 法术分类

### 3.1 新护盾法术

新护盾应配置为：

```text
Kind = Emit
SpawnMode = ForwardProjectile
ProjectilePrefab = ShieldProjectile prefab
BaseSpeed = 护盾飞行速度
BaseDamage = 0 或极低
ShieldReflectCount = 反弹次数
```

这里 `BaseDamage` 可以保留为 0。它不是靠撞人造成伤害，而是靠反弹投射物制造玩法。

### 3.2 旧护盾法术

旧护盾仍然是：

```text
Kind = StaticProjectile
SpawnMode = StaticAtPoint
ProjectilePrefab = 原地护盾 prefab
```

旧护盾负责“在某个点生成防御场”。它和新护盾不是同一个法术。

### 3.3 为什么不用 StaticProjectile

`StaticProjectile` 的核心语义是：

```text
在当前法术上下文点生成一个效果。
```

它适合：

- 陨石落点。
- 原地护盾。
- 毒雾。
- 地雷。
- 召唤物。

而新护盾的核心语义是：

```text
从施法点发射出去，在飞行中产生护盾效果。
```

所以它应该走 `Emit`。

## 4. 核心架构方案

### 4.1 推荐方案：ShieldProjectile 继承 ProjectileBase

新建一个 `ShieldProjectile`：

```text
ProjectileBase
  -> Arrow
  -> Fireball
  -> NovaFireball
  -> ShieldProjectile
```

`ShieldProjectile` 负责：

1. 像普通投射物一样接收 `SpellCaster` 的 `InitSpellMotion`。
2. 使用 `Rigidbody.linearVelocity` 从法杖方向飞出。
3. 接收现有 Modify 法术：
   - `Bounce`
   - `Gravity`
   - `Homing`
   - `Orbit`
4. 在飞行期间反弹进入范围的 `ProjectileBase`。
5. 反弹次数耗尽后销毁。
6. 到达最大生命周期后销毁。

`ShieldProjectile` 不负责：

1. 撞到敌人后造成普通伤害。
2. 撞到环境后立刻爆炸。
3. 像 Fireball 一样生成爆炸。

### 4.2 为什么不继续保留 SpellPhysicsBody

`SpellPhysicsBody` 的优点是：可以让非伤害型对象接收运动修正。

但对于“像投射物一样射出去的护盾”，它会引入重复体系：

```text
ProjectileBase 有一套运动修正
SpellPhysicsBody 又有一套运动修正
```

长期会导致两个地方都要维护：

- 重力。
- 弹跳。
- 追踪。
- 轨道。
- 初速度。
- 生命周期。

本项目当前更合理的做法是：既然新护盾本质是发射物，就直接进入 `ProjectileBase` 体系。这样它自然复用已有运动修正、同阵营投射物忽略碰撞、生命周期和 spell runtime 初始化链路。

### 4.3 ProjectileBase 需要打开一个生命周期 seam

当前 `ProjectileBase.OnCollisionEnter` 默认语义是：

```text
撞到敌人或环境
-> 结算伤害 / OnImpact / payload / Destroy
```

但 `ShieldProjectile` 的语义不是“撞到东西就命中销毁”。它更像一个飞行护盾实体。

因此需要在 `ProjectileBase` 中增加一个可重写 seam，例如：

```csharp
protected virtual bool ShouldConsumeOnCollision(Collision collision, IDamageable target)
{
    return true;
}
```

或更直接：

```csharp
protected virtual bool TryHandleCollisionBeforeDefault(Collision collision, IDamageable target)
{
    return false;
}
```

推荐使用第二种：

```text
ProjectileBase.OnCollisionEnter
-> 先查 target
-> 同阵营穿过
-> TryBounce
-> TryHandleCollisionBeforeDefault
-> 默认伤害 / OnImpact / Destroy
```

`ShieldProjectile` 重写它：

```text
如果撞到敌人：不造成伤害，不销毁，忽略或物理处理
如果撞到环境：不走默认命中销毁，让 Bounce/物理处理决定
```

但需要注意：不能破坏火球、箭、陨石的默认行为。

## 5. 组件职责

### 5.1 ShieldProjectile

新增文件：

```text
Assets/_Project/Scripts/Combat/Projectiles/ShieldProjectile.cs
```

职责：

1. 继承 `ProjectileBase`。
2. 管理护盾剩余反弹次数。
3. 保存护盾拥有者阵营和攻击者 ID，这部分可直接复用 `ProjectileBase` 的 `_attackerTeam / _attackerId`。
4. 监听子 Trigger 的反弹事件，或直接在自身 Trigger 中处理投射物进入。
5. 调用被反弹投射物的 `ReflectByShield(...)`。
6. 反弹成功后减少次数。
7. 次数耗尽后销毁自身。
8. 重写碰撞 seam，避免自己像火球一样撞到地面就爆炸。

### 5.2 ProjectileShield

上一版已有 `ProjectileShield` 组件。修正版有两种选择：

#### 方案 A：保留 ProjectileShield，改成可绑定 owner

`ProjectileShield` 继续负责 Trigger 反弹逻辑，但需要支持：

```csharp
Init(byte ownerTeam, int ownerAttackerId, int reflectCount, Collider ownerCollider)
```

或由 `ShieldProjectile` 在 Awake/Init 后把数据传给它。

优点：

- 旧静态护盾也可以继续使用 `ProjectileShield`。
- Trigger 反弹逻辑复用。

缺点：

- `ProjectileShield` 同时服务静态护盾和发射护盾，需要注意接口不要过度膨胀。

#### 方案 B：把反弹逻辑放进 ShieldProjectile

`ShieldProjectile` 自己处理 `OnTriggerEnter`。

优点：

- 新护盾投射物更集中。
- 少一个组件间初始化关系。

缺点：

- 旧静态护盾和新护盾的反弹逻辑会重复。

推荐：**方案 A，保留 `ProjectileShield` 作为通用护盾反弹组件**。

### 5.3 SpellCaster

新护盾作为普通 `Emit` 之后，`SpellCaster` 不需要为它新增特殊分支。

它会自然走：

```text
SpawnForwardProjectile
-> GetComponent<ProjectileBase>
-> WirePayload
-> ConfigureSpellMotionTarget
-> InitSpellMotion
```

这正是我们想要的结果。

### 5.4 SpellDefinition / EmitCommand / CastEvaluator

`ShieldReflectCount` 仍然需要保留，因为它是护盾法术的数据。

`ShieldReflectImpulse` 可以暂时不作为核心需求。  
因为护盾本体现在就是发射物，它飞出去已经有速度；是否被其他投射物推动可以作为后续增强。当前优先级应是：

```text
先让护盾像投射物一样飞出去并反弹其他投射物。
```

如果保留 `ShieldReflectImpulse`，它可以继续作为“被反弹投射物撞击后自身被推动”的高级参数，但不是本次修正的核心。

## 6. Prefab 设计

新护盾 prefab 推荐结构：

```text
ShieldProjectileRoot
  Rigidbody
  Collider（非 Trigger，可选，用于环境碰撞）
  ShieldProjectile
  Visual
  ShieldReflectTrigger
    SphereCollider（Is Trigger = true）
    ProjectileShield
```

关键点：

1. Root 必须有 `Rigidbody`，因为它是 `ProjectileBase`。
2. Root 必须有一个 Collider，满足 `ProjectileBase` 的 `[RequireComponent(typeof(Collider))]`。
3. 反弹范围建议使用子物体 Trigger。
4. 子物体 `ProjectileShield` 要能拿到 `ShieldProjectile` 的 owner/team 数据。
5. 不要只给 Root 一个 Trigger Collider，否则它可能不会和环境发生实体碰撞。

## 7. 数据配置

新护盾 `SpellDefinition`：

```text
DisplayName = 护盾投射物
Kind = Emit
SpawnMode = ForwardProjectile
ProjectilePrefab = ShieldProjectile prefab
BaseDamage = 0
BaseSpeed = 例如 8 到 14
DamageType = Magical
ManaCost = 根据强度设置
ShieldReflectCount = 例如 3
Icon = 新图标
```

旧护盾 `SpellDefinition` 保持：

```text
Kind = StaticProjectile
SpawnMode = StaticAtPoint
ProjectilePrefab = StaticShield prefab
ShieldReflectCount = 例如 3
```

## 8. 与现有法术系统的关系

### 8.1 Modify

因为护盾投射物是 `ProjectileBase`，所以现有 Modify 自动适用：

```text
重力修正 -> 护盾投射物
弹跳修正 -> 护盾投射物
追踪修正 -> 护盾投射物
轨道修正 -> 护盾投射物
加速修正 -> 护盾投射物
```

### 8.2 Multicast

```text
三重射击 -> 护盾投射物 -> 护盾投射物 -> 护盾投射物
```

应发射三个护盾投射物。

如果前面有轨道修正：

```text
轨道修正 -> 三重射击 -> 护盾投射物 -> 护盾投射物 -> 护盾投射物
```

三个护盾应有相位差和轨道面差异。

### 8.3 Trigger

```text
触发火球 -> 护盾投射物
```

火球命中后，payload 在命中点执行。  
`SpellCaster.RunCast(payload, hitPoint, hitDir, ...)` 会把 `hitDir` 作为 baseDir，因此护盾投射物从命中点沿命中方向射出。

这是非常符合“法术编程”的行为：触发点不只是生成位置，也提供后续发射方向。

## 10. 不做的内容

1. 不做护盾血量。
2. 不做近战打碎护盾。
3. 不做护盾撞人伤害。

1. 旧静态护盾仍然原地生成并反弹投射物。
2. 新护盾投射物能从法杖方向射出。
3. 新护盾投射物飞行中能反弹玩家和敌方投射物。
4. 敌方投射物被反弹后能伤害敌人。
5. `重力修正 -> 护盾投射物` 生效。
6. `弹跳修正 -> 护盾投射物` 生效。
7. `追踪修正 -> 护盾投射物` 生效。
