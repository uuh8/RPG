# 保护盾静态投射物设计

创建时间：2026-07-05

## 1. 功能目标

新增一个静态投射物类法术“保护盾”。它释放后不向前飞行，而是在释放点生成一个球形护盾。护盾可以反弹进入护盾范围的投射物，并且有反弹次数限制；次数耗尽后护盾立刻销毁。

这个法术的设计目标不是单纯防御，而是增加法术编程系统的弹道趣味：玩家自己的投射物也可以被护盾反弹，从而制造折射弹道；敌方投射物被反弹后会变成玩家阵营的投射物，可以反过来伤害敌人。

## 2. 玩家可见效果

1. 玩家把“保护盾”放进法杖并释放。
2. 护盾在玩家释放点原地生成。
3. 任意 `ProjectileBase` 投射物进入护盾球体范围时，会按球面法线反射出去。
4. 玩家阵营投射物也会被反弹，用于制造弹道变化。
5. 被反弹的投射物不会攻击到释放护盾的玩家。
6. 敌方投射物被反弹后会改为护盾释放者阵营，因此可以对敌方造成伤害。
7. 护盾每反弹一次扣一次次数，次数耗尽时立刻销毁。

## 3. 核心规则

### 3.0 静态投射物通用语义

保护盾必须被当作普通 `SpellKind.StaticProjectile` 处理，而不是独立的硬编码技能。

这意味着：

1. 直接释放时，它在当前释放点生成；通常就是玩家的法杖释放点附近。
2. 如果它被触发类投射物作为 payload 捕获，例如：

```text
触发火球 -> 保护盾
```

那么触发火球命中后，保护盾会在命中点生成，而不是回到玩家位置生成。

3. 它可以继承触发前已经累积的 `CastModifierState`。也就是说，如果未来某些修正字段对静态物有意义，护盾也应该走同一条快照链路，而不是绕过解释器。
4. 本次实现中，保护盾至少需要从 `SpellDefinition -> EmitCommand -> SpellCaster -> ProjectileShield` 快照并使用 `ShieldReflectCount`。其他运动修正如追踪、轨道、重力对护盾本体暂时没有意义，可以被安全忽略，但不能破坏现有 payload mods 继承机制。

### 3.1 反弹对象

护盾反弹所有进入 Trigger 范围的 `ProjectileBase`：

- 玩家自己的投射物：反弹。
- 队友投射物：反弹。
- 敌方投射物：反弹，并转为护盾释放者阵营。

不处理非投射物对象，例如玩家、敌人、地形、普通触发器。

### 3.2 阵营和伤害归属

任何被护盾反弹的投射物，都会被设置为护盾释放者的归属：

```text
projectile.Team = shield.Team
projectile.AttackerId = shield.AttackerId
```

这样有两个结果：

1. 玩家自己的投射物被反弹后仍然属于玩家阵营，不会伤害玩家。
2. 敌方投射物被反弹后变成玩家阵营，反弹回敌人时可以伤害敌人。

这符合项目已有 `ProjectileBase` 的同阵营过滤逻辑：投射物命中与自己同阵营的 `IDamageable` 时会 `IgnoreCollision` 并不结算伤害。

### 3.3 反弹方向

反弹使用物理反射公式：

```text
reflected = Vector3.Reflect(incoming, normal)
```

其中：

- `incoming`：投射物当前速度方向。
- `normal`：从护盾球心指向投射物当前位置的单位向量。

这样护盾表现为一个球面反射体，而不是固定朝某个方向弹开。

### 3.4 次数限制

护盾持有 `ReflectCount`：

```text
每成功反弹一个投射物 -> ReflectCount - 1
ReflectCount <= 0 -> Destroy(shield)
```

次数耗尽后立刻销毁，不保留无功能视觉体。

### 3.5 生成方式

保护盾是 `SpellKind.StaticProjectile`，但它不是陨石的 `SkyfallAtPoint`。因此需要新增一个静态原地生成方式：

```text
SpellSpawnMode.StaticAtPoint
```

生成规则：

```text
SpellCaster.RunCast
-> EmitCommand.SpawnMode == StaticAtPoint
-> Instantiate(prefab, spawnPos, prefab rotation)
-> 初始化 ProjectileShield(team, attackerId, reflectCount)
```

## 4. 架构方案

### 4.1 涉及模块

```text
Game.Skills
  SpellKind / SpellSpawnMode / SpellDefinition / EmitCommand / CastEvaluator

Game.Character
  SpellCaster

Game.Combat
  ProjectileBase
  ProjectileShield
```

### 4.2 Game.Skills

`Game.Skills` 保持纯数据和纯解释器，不直接反弹投射物。

需要扩展：

1. `SpellSpawnMode` 增加 `StaticAtPoint`。
2. `SpellDefinition` 增加静态投射物护盾相关数据：
   - `ShieldReflectCount`
   - 可选：`StaticLifetime`
3. `EmitCommand` 快照这些数据。
4. `CastEvaluator.BakeEmit` 把 `SpellDefinition` 数据写入 `EmitCommand`。

### 4.3 Game.Character

`SpellCaster` 是 Unity runtime 桥接层，负责根据 `EmitCommand` 实例化对象。

需要扩展：

1. `RunCast` 的 `switch (cmd.SpawnMode)` 增加 `StaticAtPoint` 分支。
2. 新增 `SpawnStaticProjectileAtPoint(...)`。
3. 实例化后查找 `ProjectileShield`，并注入：
   - `team`
   - `attackerId`
   - `reflectCount`
   - `casterCollider`

`SpellCaster` 不负责计算反弹方向，也不直接修改投射物速度。反弹属于 Combat 交互逻辑。

### 4.4 Game.Combat

新增 `ProjectileShield`：

```text
Assets/_Project/Scripts/Combat/Projectiles/ProjectileShield.cs
```

职责：

1. 持有护盾释放者阵营和攻击者 id。
2. 持有剩余反弹次数。
3. 在 `OnTriggerEnter(Collider other)` 中检测 `ProjectileBase`。
4. 计算球面反射法线。
5. 调用 `ProjectileBase.ReflectByShield(...)`。
6. 扣反弹次数，次数耗尽后销毁护盾。

扩展 `ProjectileBase`：

新增公开方法，例如：

```csharp
public bool ReflectByShield(Vector3 normal, byte newTeam, int newAttackerId)
```

职责：

1. 读取当前 `Rigidbody.linearVelocity`。
2. 计算 `Vector3.Reflect`。
3. 保持原速度大小，只改变方向。
4. 改写 `_attackerTeam` 和 `_attackerId`。
5. 更新 `_launchVelocity`，避免后续同阵营穿过逻辑恢复成旧速度。
6. 清理或更新同阵营碰撞忽略关系。

## 5. Prefab 要求

保护盾 Prefab 需要：

1. 一个球形视觉体。
2. 一个 `Collider`，建议 `SphereCollider`。
3. `Collider.isTrigger = true`。
4. 挂 `ProjectileShield`。
5. 不需要 `ProjectileBase`，因为护盾本身不是飞行投射物；它是“投射物交互体”。
6. 如果需要自动消失，可以在 `ProjectileShield` 中支持 lifetime，或先由粒子系统/Prefab 自己处理视觉。

## 6. 为什么护盾用 Trigger

不用普通 Collision 的原因：

`ProjectileBase.OnCollisionEnter` 目前会在撞到非同阵营、非可反弹环境时执行命中、触发、销毁。如果保护盾使用普通 Collider，投射物可能先走自己的命中销毁逻辑，护盾就来不及接管反弹。

使用 `Trigger` 后，护盾可以通过 `OnTriggerEnter` 主动处理投射物，不让投射物把护盾当作普通命中目标。

## 7. 测试重点

### 7.1 纯逻辑 / 编译测试

1. `SpellSpawnMode.StaticAtPoint` 不破坏旧枚举值。
2. `CastEvaluator` 能把 `StaticProjectile` 的护盾配置写入 `EmitCommand`。
3. `ProjectileBase.ReflectByShield` 能编译并更新速度 / 阵营 / 攻击者。

### 7.2 Play Mode 测试

1. 直接释放保护盾，护盾在玩家释放点生成。
2. 玩家火球打到护盾后会反弹。
3. 玩家火球被反弹后不会伤害玩家。
4. 敌方火球打到护盾后会反弹。
5. 敌方火球被反弹回敌人后能伤害敌人。
6. 护盾反弹次数耗尽后立刻消失。
7. 护盾 Prefab 的 Trigger 没有错误拦截玩家移动。

## 8. Editor 配置要求

1. 新建 `SpellDefinition`：`Spell_Static_Shield`。
2. 设置：
   - `Kind = StaticProjectile`
   - `SpawnMode = StaticAtPoint`
   - `ProjectilePrefab = 保护盾 Prefab`
   - `ManaCost = 根据平衡配置`
   - `ShieldReflectCount = 例如 3`
3. 将该法术加入 `SpellLibrary`。
4. 给保护盾配置 Icon。
5. 确保护盾 Prefab：
   - 有 `SphereCollider`
   - `Is Trigger = true`
   - 有 `ProjectileShield`
   - Collider 半径与视觉球体大小匹配

## 9. 暂不做的内容

1. 不做护盾血量。
2. 不做护盾被近战攻击打碎。
3. 不做队伍白名单配置。
4. 不做护盾移动或跟随玩家。
5. 不做多层护盾之间的复杂连锁反弹规则。

这些都可以作为后续增强，但本阶段先完成最核心的“静态生成 + 投射物反弹 + 次数耗尽销毁”。
