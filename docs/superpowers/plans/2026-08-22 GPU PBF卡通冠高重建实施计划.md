# GPU PBF 卡通冠高重建实施计划

> **执行要求：** 实施时使用 `superpowers:executing-plans` 按 Task 顺序执行，并严格遵循 `test-driven-development`、`verification-before-completion`。本任务未授权 SubAgent，只允许当前主 Agent inline 执行。

**Goal：** 在不改变 PBF 粒子、Gameplay Occupancy、碰撞、分裂、融合与 Sleeping 的前提下，让静止水滩呈现“边缘薄、中心明显隆起”的卡通化连续表面。

**Architecture：** 保留 `Game.ElementField` 作为 Simulation Truth；新增效果完全属于 `Game.Rendering` 的 Surface Reconstruction。Anisotropy 邻域阶段为每个粒子计算一个 0–1 的局部支持度，Density 阶段只把邻居充分的内部粒子 Kernel 向世界空间 `+Y` 单向延展，边缘与孤立液滴保持原形；Marching Cubes 与材质继续消费同一 Density Texture。

**Tech Stack：** Unity 6.3、URP 17.3、C#、HLSL Compute Shader、GraphicsBuffer、3D `R32_SFloat` Density Texture、Marching Cubes、NUnit EditMode/GPU Fixture。

**Spec：** 2026-08-22 用户已确认采用 Presentation-only `Stylized Crown Reconstruction`；依照项目约定不创建独立 spec，本计划包含完整设计。

## Global Constraints

- 不修改 `GpuPbfFluidRuntime` 的粒子位置、速度、Tensile、Cohesion、Collision 或 Sleep 数学。
- `Game.Rendering` 只能读取 `IFluidGpuSource`，不得写回 Simulation Buffer 或 Gameplay Occupancy。
- `CrownHeightRatio = 0` 或 `UseStylizedCrown = false` 时必须回到既有 Density 行为。
- Crown 只沿世界空间 `+Y` 扩展 Kernel 上半部；下半部不扩张，避免视觉表面向地板内部增厚。
- 最长 Density Kernel 支持域仍限制为 `2 * SmoothingRadius`，候选 Hash Cell 半径保持最多 2，即最坏 `5³ = 125` 个 Cell。
- 当前 Water 已启用 Anisotropy；该路径复用既有邻域扫描，不为每个 Voxel 增加新的粒子邻域统计。
- 新增长期 GPU Buffer 只允许一个 `float/particle` Support Buffer；8192 粒子约增加 32 KiB VRAM。
- Runtime 热路径不得产生 `GC Alloc`，不得使用 LINQ、Closure 或每帧 `new`。
- Profile 仍在 Renderer 初始化时生成不可变 Snapshot；Inspector Tooltip 和解析文档必须明确“停止并重新进入 Play Mode 才生效”。
- 外部资产依赖：无。不需要 Texture、Normal Map、Model、VFX、Audio、Font 或第三方 Package。

## 设计与取舍

### 为什么继续放大 Tensile 无法解决

`Tensile Constraint` 的修正方向来自两个粒子的连线。水滩落成单层后，这些连线主要位于 XZ 平面，因此强度增大首先造成横向收缩，而不是稳定的 Y 轴冠高；过大的位置修正还会重新注入速度并破坏边缘 Sleeping。截图中的大数值又是在 Play Mode 内修改，而 `GpuPbfFluidRuntime.Awake -> TryInitialize -> CreateSettings` 已经保存旧 Snapshot，所以该次试验并未改变当前 Solver。

### 为什么选择 Rendering-only Crown

卡通冠高是艺术夸张，不应改变角色是否接触水、反应消耗量或液滴动力学。将其放入 Density Reconstruction 后，Simulation 继续回答“水在哪里、怎样流”，Presentation 回答“表面看起来多厚”；禁用效果即可无损回滚。代价是画面顶面可能比 Gameplay Occupancy 高约一个 `SmoothingRadius`，解析文档和面试说明必须明确这是表现层偏差。

### 核心数学

邻域阶段对每个粒子统计 Compact Support 内的邻居数量 `n`，转成内部支持度：

```text
support = saturate((n - edgeCount) / (interiorCount - edgeCount))
weight  = pow(support, crownFalloff)
desiredUpScale = 1 + crownHeightRatio * weight
```

默认 `edgeCount=4`、`interiorCount=12`、`crownHeightRatio=0.8`、`crownFalloff=1.5`。孤立液滴与边缘接近 0，水滩内部接近 1。

对 Density Sample，只有位于粒子中心上方的世界空间 Y 差值被压缩后送入 Kernel：

```text
if sample.y > particle.y:
    adjustedSample.y = particle.y + (sample.y - particle.y) / appliedUpScale
```

Sample 在 Kernel Space 中移动得更慢，等价于粒子 Density Kernel 只向上延展。为避免 Anisotropy 与 Crown 相乘后超过 Spatial Hash 查询范围，使用矩阵对世界 Up 的度量：

```text
baseUpMetric = length(A * worldUp)
safeUpScale = max(1, 2 * baseUpMetric)
appliedUpScale = min(desiredUpScale, safeUpScale)
```

这样最终世界空间向上支持域不会超过 `2h`，其中 `h = SmoothingRadius`。

## 回滚与常见失败

- **需要立即回滚视觉效果：** 在 `LiquidRenderProfile_Water` 关闭 `Use Stylized Crown` 或设 `Crown Height Ratio=0`；无需回滚 PBF。
- **调参没有变化：** 多半是在 Play Mode 内修改了初始化 Snapshot；停止后编辑 Asset，再重新进入。
- **整滩水同样厚：** Support 阈值过低；先提高 `Crown Interior Neighbor Count`，不要增加 Tensile。
- **中心出现尖塔：** Height Ratio 过高或 Falloff 过低；先降低 Height Ratio，再提高 Falloff。
- **边缘也被抬高：** `Crown Edge Neighbor Count` 太低，或 Support Buffer 未在 TopologyVersion 变化后重算。
- **表面缺块：** 检查 `appliedUpScale` 是否突破 `2 * baseUpMetric`，以及 Density Candidate Cell Radius 是否为 2。
- **孤立粒子长高：** inactive/低邻居 Support 没有清零；用 3×3+isolated GPU Fixture 定位。
- **画面凸起但角色未 Wet：** 这是预期架构边界；视觉表面高于 Simulation Occupancy，不能把 Rendering Mesh 当 Gameplay Collider。
