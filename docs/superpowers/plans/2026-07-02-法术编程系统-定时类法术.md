# 法术编程系统 · 定时类法术 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 新增“定时类法术”：投射物存活满指定时间后销毁自己，并在当前位置沿当前飞行方向释放后续 payload 法术；如果提前命中或销毁，则不释放定时 payload。

**Architecture:** 将 Phase D 的 `bool IsTrigger` 升级为 `PayloadTriggerMode` 枚举，让普通投射物、命中触发投射物、定时触发投射物都保持为 Emit 法术的数据变体。`CastEvaluator` 仍捕获严格后缀 payload；`ProjectileBase` 只暴露通用定时事件；`SpellCaster` 根据 payload 触发模式绑定命中或定时事件并复用 `RunCast` 递归施法。

**Tech Stack:** Unity 6.3 / C# / ScriptableObject / Rigidbody + Collider / `ProjectileBase` lifecycle events / `CastEvaluator` EditMode NUnit tests / Unity Editor 手动资产配置与 Play 验证。

- [ ] **Step 2: Update `BakeEmit`**

Replace `BakeEmit` with:

```csharp
        /// <summary>把一个 Emit 法术按当前修正快照算出最终产出指令。</summary>
        private static EmitCommand BakeEmit(SpellDefinition spell, CastModifierState mods, IReadOnlyList<SpellDefinition> payload)
        {
            float damage = (spell.BaseDamage + mods.DamageAddFlat) * mods.DamageMul;
            float speed = spell.BaseSpeed * mods.SpeedMul;
            PayloadTriggerMode trigger = payload != null && payload.Count > 0
                ? spell.PayloadTrigger
                : PayloadTriggerMode.None;
            float delay = trigger == PayloadTriggerMode.AfterDelay ? spell.PayloadDelaySeconds : 0f;
            return new EmitCommand(spell.ProjectilePrefab, damage, speed, spell.DamageType,
                                   mods.SpreadDegrees, spell.CastSfx, payload, mods, trigger, delay);
        }
```

Rationale:

```text
[定时火球] 这种空 payload 情况下，求值器仍产出定时火球本体，但 command.PayloadTrigger 降为 None，运行时不会绑定空 payload 定时事件。
```

- [ ] **Step 2: Add `Update` timer logic**

Add this method above `FixedUpdate`:

        protected virtual void Update()
        {
            if (_consumed || !_timedTriggerArmed) return;

            _timedTriggerRemaining -= Time.deltaTime;
            if (_timedTriggerRemaining > 0f) return;

            _consumed = true;
            TimedTriggerElapsed?.Invoke(transform.position, ResolveCurrentDirection());

        }

Do not put this in `FixedUpdate`; this is gameplay timing, not physics integration.

- [ ] **Step 3: Add `ArmTimedTrigger`**

Add this public method after `Init` or before `OnCollisionEnter`:

```csharp
        /// <summary>
        /// 开启定时触发。delaySeconds <= 0 时在下一帧触发，避免在 Arm 调用栈内重入施法。
        /// </summary>
        public void ArmTimedTrigger(float delaySeconds)
        {
            _timedTriggerArmed = true;
            _timedTriggerRemaining = Mathf.Max(0f, delaySeconds);
        }
```

- [ ] **Step 4: Add current direction helper**

Add this private helper near `OnCollisionEnter`:

```csharp
        private Vector3 ResolveCurrentDirection()
        {
            Vector3 v = _rb != null ? _rb.linearVelocity : Vector3.zero;
            if (v.sqrMagnitude > 1e-6f)
                return v.normalized;
            return transform.forward;
        }
```

                if (cmd.HasPayload)

                if (cmd.HasPayload)
                {
                    IReadOnlyList<SpellDefinition> payload = cmd.Payload;
                    CastModifierState payloadMods = cmd.PayloadMods;

                    switch (cmd.PayloadTrigger)
                    {
                        case PayloadTriggerMode.OnImpact:
                            proj.Impacted += (hitPoint, hitDir) =>

                                RunCast(payload, 1, payloadMods, position, direction, team, attackerId, casterCollider);
                            proj.ArmTimedTrigger(cmd.PayloadDelaySeconds);
                            break;
                    }
                }

## Implementation Notes

- `PayloadTriggerMode.AfterDelay` is a gameplay trigger, not the same as `_maxLifetime`.
- `_maxLifetime` self-destroy does not release payload.
- `ArmTimedTrigger` should only be called when `cmd.HasPayload` is true and `cmd.PayloadTrigger == AfterDelay`.
- `PayloadDelaySeconds <= 0` triggers on the next `Update`, not immediately inside `ArmTimedTrigger`.
- Event callbacks capture local `payload` and `payloadMods`, preserving per-projectile payload state.
- If future features add loops, copied full wands, or non-suffix payloads, revisit recursion guards and active projectile caps.
