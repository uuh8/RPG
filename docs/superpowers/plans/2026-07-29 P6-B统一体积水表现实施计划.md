## 已确认根因与成功标准

### 当前根因

1. 旧 Builder 使用 `Block Surface Meshing`：每格顶面严格覆盖一个 Cell 的 XZ 正方形，所以岸边只能沿 `0.25m` Cell 边界形成台阶。
2. 旧高度公式 `surfaceY = cellBottomY + cellSize × Amount/255` 对所有 Water Cell 一视同仁。空中低 Amount Cell 因而成为贴在 Cell 底部的厘米级薄片。
3. `PF_ElementWaterProjectile` 当前 `TotalAmount=1600`、`Radius=0.75m`、`UseLinearFalloff=true`。典型命中可覆盖约百余个 Cell，许多空中 Cell Amount 很低；旧 Builder 忠实地把它们表现成多层横条。
4. Water Shader 的 Noise 只扰动 Lighting Normal，不移动 Geometry Vertex，因此调 Wave/Fresnel/Foam 不能改变轮廓。

### 玩家可见成功标准

- 地面水滩的外边缘不再由完整正方形 Cell 台阶组成；斜边和圆弧由连续 Polygon 近似。
- 水滩仍有底部支撑和可见厚度，不是没有侧壁的一张透明 Plane。
- 空中至少一个低 Amount Water Cell 也能生成 X/Y/Z 三轴均有范围的封闭体积，而不是水平薄片。
- 相邻空中 Water Cell 合并为一个连续水团，不出现每格一颗互不相连的珠子。
- 容器底部/水下方存在 Solid 或 Water 时，水体从支撑面向上填充；多层水形成连续体积，顶部自由表面近似水平。
- P7/P8 跨 Chunk 水体无裂缝、重复面或 Noise 相位重置。
- Water Gameplay 的总 Amount、流动结果、Wet 与 Water/Fire Reaction 测试结果不改变。

Smooth Union Radius         = 0.16 Cell

空中相邻 Water Cell 不只依靠球半径碰撞。Primitive 会检查六邻域：朝相邻 Water 的方向延伸到公共 Cell Boundary，朝 Empty 的外轮廓方向才使用 Amount 驱动的 Radius。这样内部连接连续，外轮廓仍会随 Amount 收缩。

- Supported 判断：

```csharp
supported = world.IsSolid(cell + Vector3Int.down)
    || IsWater(world, cell + Vector3Int.down);
```

Supported Cell 使用从 Cell Bottom 开始的 Rounded Box：

```text
height = max(Amount / 255, MinimumSupportedHeight)
bottom = cell.y
top    = cell.y + height
```

Unsupported Cell 使用以 Cell Center 为中心、按六邻域向连接方向延伸的 Rounded Box / Droplet Primitive；开放方向半径为：

```text
amount01 = Amount / 255
radius   = lerp(MinimumAirborneRadius,
                MaximumAirborneRadius,
                cbrt(amount01))
```

所有 Primitive 用 Polynomial Smooth Minimum 合并：

```text
h = saturate(0.5 + 0.5 × (b-a) / k)
smin(a,b,k) = lerp(b,a,h) - k × h × (1-h)
```

- [x] **Step 4：实现 Rounded Box SDF、邻域连接和 Smooth Union**

Rounded Box 使用标准 Signed Distance：

```csharp
float effectiveRadius = Mathf.Min(
    roundRadius,
    Mathf.Min(halfExtents.x, Mathf.Min(halfExtents.y, halfExtents.z)));
Vector3 innerHalfExtents = halfExtents - Vector3.one * effectiveRadius;
Vector3 q = Abs(point - center) - innerHalfExtents;
float outside = Max(q, Vector3.zero).magnitude;
float inside = Mathf.Min(Mathf.Max(q.x, Mathf.Max(q.y, q.z)), 0f);
return outside + inside - effectiveRadius;
```

先从 Half Extents 中扣掉圆角再减回 `effectiveRadius`，才能让圆角发生在原始 Bounds 内部；
若直接对原始 Half Extents 再减 Radius，会把整个 Primitive 向外膨胀。浅水的 Y Half
Extent 可能小于 Profile 圆角，因此 Effective Radius 必须同时受 X/Y/Z 最小半轴限制。

采样只遍历 Sample 所在 Global Cell 周围固定 `3×3×3` 邻域，不创建集合。若 Sample 所在 Cell 为 Solid，返回正距离，防止水面进入 Collision Solid。

{

        IElementWorldReadOnly world,
        ElementChunkKey chunkKey,
        in WaterVolumeMeshingSettings settings,

        List<Vector3> vertices,
        List<Vector3> normals,
        List<Vector2> uvs,

**Surface Nets 采样约定：**

```text
N = ChunkSize × SamplesPerCell
sample spacing = 1 / SamplesPerCell Cell
Scalar sample logical range = [-2, N+1]
Gradient logical range      = [-1, N]
Dual cell logical range     = [-1, N-1]
Mesh vertex position        = Chunk-local Meter
Implicit field query        = Global Cell Space
UV                           = Global World Meter
```

Scalar 需要两层负向 Halo 和一层正向 Halo：Chunk 边缘的 Dual Cell 要读取外侧 Sample，而该 Sample 的中心差分 Normal 又要再向外读取一个 Sample。相邻 Chunk 对相同 Global Sample 调用完全相同的纯函数，因此 Seam Position 与 Normal 一致。

- [x] **Step 4：采样 Scalar 并用中心差分计算 Gradient**

```text
gradient.x = scalar(x+1,y,z) - scalar(x-1,y,z)
gradient.y = scalar(x,y+1,z) - scalar(x,y-1,z)
gradient.z = scalar(x,y,z+1) - scalar(x,y,z-1)
normal     = normalize(gradient)
```

Signed Distance 约定为内部负、外部正，因此 Gradient 指向外侧。长度接近零时使用该 Dual Cell 交叉边法线平均作为回退。

- [x] **Step 5：为每个符号混合的 Dual Cell 生成一个 Vertex**

检查 Cube 12 条 Edge；仅当端点 Scalar 一正一负时计算交点：

```text
t = a / (a - b)
intersection = lerp(positionA, positionB, t)
dualVertex = 所有交点的算术平均
dualNormal = normalize(所有 lerp(gradientA, gradientB,t) 的平均)
```

一个 Dual Cell 最多生成一个 Vertex，避免 Marching Tetrahedra 的重复 Vertex 与大容量 Buffer。

- [x] **Step 6：沿发生符号变化的 Sample Edge 连接四个 Dual Vertex**

每条符号变化 Edge 周围有四个 Dual Cell。四个 Vertex 都存在时生成一个 Quad（两个 Triangle）；由 Scalar 正负决定 Winding，使 Triangle Normal 与平均外法线同向。Chunk Ownership 使用 Edge 的 Global 最小 Sample 坐标，保证跨页 Edge 只由一个 Chunk 输出一次。

## Debug 与回滚路径

### 完全没有水

检查顺序：

```text
ElementWorldRuntime IsInitialized
→ Volume Profile 是否绑定
→ Visible Element Chunk Count
→ Assigned View Count
→ Dirty/Rebuild Count
→ Builder Indices.Count
→ MeshRenderer.enabled
→ Shader Compile Error
```

Gameplay 有 Wet 但 `Indices.Count=0` 时，问题在 Profile/Implicit Field/Surface Nets，不要修改 Deposit 或 Solver。

### 水体进入地面或瓶壁

先用 Debug Gizmo 检查 SolidMask 是否真正包含对应 Cell。若 `IsSolid=false`，属于 Solid Bake/Layer 配置；若 `IsSolid=true` 但水面仍穿入，才检查 Implicit Field 对 Solid Sample 的差集规则。

### Chunk 接缝

冻结 Simulation，比较接缝两侧相同 Global Sample 的 Scalar、Gradient 和生成 Vertex。若数据相同但画面接缝，检查 Mesh Transform/Normal/Triplanar；若数据不同，检查 27-Chunk Signature、Global Cell 坐标和 Halo Ownership。

### 空中水仍像薄片

记录该 Cell 的 Amount、Supported 判断、六邻域 Water Mask 和 Primitive Bounds。若错误地 `Supported=true`，检查下方 Water/Solid；若 Bounds 已有三轴范围但画面仍像薄片，检查 Camera 角度、Cull、透明 Alpha 和 Surface Nets Normal，不要先增加 TotalAmount。

### 性能超预算

2026-07-29 首次 P7 Scene Playthrough 已出现约 `2.9 FPS / 349.4 ms` 的阻断性回归。
根因不是“采样密度天然过高”，而是空 `Resident Chunk` 也会 Acquire View，并进入完整
SDF / Surface Nets。已增加 `WorldWaterChunkRelevance` Broad Phase：

```text
RED   最小空 Chunk：13,824 次 TryGetCell
GREEN 修复后：          8 次 TryGetCell
```

Renderer 现在只为含水 Chunk Acquire View，水流走后 Release；Builder 本身也会在空 Chunk
提前返回。这个修复优先于降低质量参数，因为它删除的是无意义工作，不牺牲水面轮廓。

第一次修复后用户复验：无水场景恢复到 `88.3 FPS / 11.3 ms`，但生成一颗水球后仍为

## Phase 4：Visual Density Field 连续化修正

### 已确认的新根因与设计边界

2026-07-29 第三次 P7 Scene Playthrough 表明，前两轮修复解决了“完全不可见”和主要 CPU
浪费，却没有解决 Cell 到连续表面的表达模型：

1. 每个原始非空 Water Cell 仍直接生成一个 `WorldWaterPrimitive`。
2. 只有六方向直接相邻 Cell 才延伸到公共边界；对角相邻、隔着一个低密度 Cell 的水不会连接。
3. 当前 `_minimumAirborneRadius=0.30 Cell`，两个未连接 Cell 的直径只有 `0.60 Cell`；
   `_smoothUnionRadius=0.16 Cell` 不能跨越剩余间隙。
4. 先前为了强制产生符号变化，把 Supported Water 最低构网高度提高到
   `1/SamplesPerCell + 0.01 = 0.51 Cell`。这能让单格水可见，却也会把所有低 Amount 残余
   强制画成独立小块；透明材质只留下 Fresnel/Specular 亮点，形成“地面小点点”。
5. Shader 的 Vertex Stage 不移动 Position，因此空中尖片与碎块不是 Wave 参数造成的；
   Shader 只放大了低多边形独立组件的视觉割裂。

用户已经确认采用 `Visual Density Field`：Gameplay 仍严格读取原始 Water Cell；Presentation
允许在不跨越 Solid 的前提下连接相邻/对角低量水，并隐藏完全孤立的极低量残余 Cell。

本 Phase 不需要任何用户提供的 Texture、Model、VFX 或其他外部 Asset。复用现有
`ElementWaterVolumeRenderProfile_P6B.asset` 与 `M_ElementWater_Handwritten.mat`；第一轮不改
材质，以便明确判断几何修复是否生效。

### 数据流

```text
CachedWaterAmounts（Gameplay Snapshot，只读）
→ 将原始 Cell 分为 Supported Seed / Airborne Seed
→ 两个预分配 float[] 执行 Separable [1,2,1] Filter
   Supported：X → Z
   Airborne： X → Y → Z
→ Density Threshold + 两类 Density 竞争
→ CachedVisualWaterAmounts / CachedVisualSupportedMask
→ 每个 Visual Cell 预计算一个 WorldWaterPrimitive
→ 现有 Cell-centric Scalar Field
→ Surface Nets
```

Filter 使用固定 Kernel，但用 `strength` 在原值与平滑值之间插值：

```text
kernel(center, negative, positive)
= (negative + 2 × center + positive) / 4

output
= lerp(center, kernel, smoothingStrength)
```

若相邻 Cell 是 Solid，则使用 `center` 代替该邻居，即 `Reflective Boundary`。这代表密度在墙
面反射而不是穿墙或凭空损失；开放 Empty Cell 仍按 0 参与，因此孤立低量 Seed 会被摊薄，

```csharp
public static void Build(
    WaterVolumeMeshingWorkspace workspace,
    in WaterVolumeMeshingSettings settings)
{
    Array.Clear(workspace.CachedVisualWaterAmounts, 0,
        workspace.CachedVisualWaterAmounts.Length);
    Array.Clear(workspace.CachedVisualSupportedMask, 0,
        workspace.CachedVisualSupportedMask.Length);

    Seed(workspace, workspace.VisualDensityBufferA, supportedSeed: true);
    FilterAxis(workspace, workspace.VisualDensityBufferA,
        workspace.VisualDensityBufferB, 1, 0, 0,
        settings.SupportedSmoothingStrength);
    FilterAxis(workspace, workspace.VisualDensityBufferB,
        workspace.VisualDensityBufferA, 0, 0, 1,
        settings.SupportedSmoothingStrength);
    Commit(workspace, workspace.VisualDensityBufferA,
        settings.VisualDensityThreshold, supported: true);

    Seed(workspace, workspace.VisualDensityBufferA, supportedSeed: false);
    FilterAxis(workspace, workspace.VisualDensityBufferA,
        workspace.VisualDensityBufferB, 1, 0, 0,
        settings.AirborneSmoothingStrength);
    FilterAxis(workspace, workspace.VisualDensityBufferB,
        workspace.VisualDensityBufferA, 0, 1, 0,
        settings.AirborneSmoothingStrength);
    FilterAxis(workspace, workspace.VisualDensityBufferA,
        workspace.VisualDensityBufferB, 0, 0, 1,
        settings.AirborneSmoothingStrength);
    Commit(workspace, workspace.VisualDensityBufferB,
        settings.VisualDensityThreshold, supported: false);
}
```

    || workspace.TryGetCachedWater(globalCell + Vector3Int.down, out _);

    ? workspace.CachedWaterAmounts[index] / 255f

```csharp
private static float FilterAxisSample(
    WaterVolumeMeshingWorkspace workspace,
    float[] source,
    int x,
    int y,
    int z,
    int dx,
    int dy,
    int dz,
    float strength)
{
    int centerIndex = workspace.CellCacheIndex(x, y, z);
    if (workspace.CachedSolidMask[centerIndex])
        return 0f;

    float center = source[centerIndex];
    float negative = ReadOpenOrReflect(
        workspace, source, x - dx, y - dy, z - dz, center);
    float positive = ReadOpenOrReflect(
        workspace, source, x + dx, y + dy, z + dz, center);
    float filtered = (negative + 2f * center + positive) * 0.25f;
    return Mathf.LerpUnclamped(center, filtered, strength);
}
```

`ReadOpenOrReflect` 的完整边界语义：

```csharp
private static float ReadOpenOrReflect(
    WaterVolumeMeshingWorkspace workspace,
    float[] source,
    int x,
    int y,
    int z,
    float center)
{
    if (!workspace.TryGetCellCacheIndex(x, y, z, out int index))
        return center;
    return workspace.CachedSolidMask[index] ? center : source[index];
}
```

`Commit` 对低于 Threshold 或处于 Solid 的目标不写入。Supported Pass 还必须要求
`IsCachedVerticallySupported(targetCell)`，防止二维 Filter 把水面越过平台边缘悬在空中。
Supported 先提交；Airborne 后提交时仅当它的 Density 严格大于
`CachedVisualWaterAmounts[index] / 255f` 才覆盖 Amount。覆盖后的 Mask 不是无条件 false：
目标下方已有 Solid/Gameplay Water 时仍标为 Supported，否则才标为 Airborne。两个 Commit
全部结束后只遍历一次 Visual Amount 数组，令 `CachedVisualWaterCellCount` 等于非零项数量。

Supported Seed 只执行 X/Z；Airborne Seed 执行 X/Y/Z。每个 Pass 完整覆盖目标 Buffer，不能依赖
上次 Rebuild 遗留值。提交 Airborne 时与已有 Supported Visual Density 比较，较大者决定
`CachedVisualSupportedMask`；Amount 用 `Mathf.RoundToInt(density * 255f)` Clamp 到 byte。

### 类型一致性

- Profile 唯一输出 `WaterVolumeMeshingSettings`。
- Implicit Field 与 Builder 都按 Global Cell Space 读取同一个 Settings Snapshot。
- 一个 `WorldWaterChunkView` 唯一持有一个与 ChunkSize/SamplesPerCell 匹配的 Workspace。
- Builder 输出四个长度一致的 Buffer：Vertices、Normals、Uvs、Indices。
- Renderer 直接上传 Builder Normal，不再重新计算 Flat Normal。
- Gameplay Snapshot 与 Visual Cache 是两套命名明确的数组；Filter 只从前者写向后者。
- Visual Filter 只复用 `BufferA/BufferB`；Supported 与 Airborne 不各自长期占用两套 float 临时数组。

### 非目标

- 不实现真实 Navier–Stokes、Pressure Projection、Velocity Field 或 Surface Tension Gameplay。
- 不修改水球的 TotalAmount/Radius。
- 不实现透明瓶子的完整折射、Backface Thickness Buffer 或 Order-Independent Transparency。
- 不把 P6-A 固定 Field 一并迁移。
- 不修改 Gameplay Water Flow 来让画面更连贯；视觉连续性只在 `Game.Rendering` 解决。
- 不实现 Connected Component Flood Fill、Ellipsoid 拟合或 Mesh Laplacian Smoothing。
- 不引入 Job/Burst/Compute Shader；只有 Phase 3 Profiler 证明 Main Thread Meshing 超预算后，才另立优化计划。
