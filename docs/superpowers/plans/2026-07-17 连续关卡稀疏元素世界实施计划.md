# 连续关卡稀疏元素世界实施计划

> **阶段状态（2026-07-18）：已完成。** P6-B Task 0～6 与 Water/Fire Demo Gate 已通过；本计划冻结为实施记录。Poison/Sticky/Steam 不再作为 P6 完成条件，首个连续灰盒关卡及单局流程转入 `docs/superpowers/plans/2026-07-18 P7完整单局Demo实施计划.md`。

> **执行方式：** 在当前会话中按 Task 顺序执行，每个 Task 都经过 TDD、静态检查、Unity Test Runner 和用户 Editor Gate；遵守用户要求，不使用 SubAgent。

**Goal：** 把当前仅覆盖 `8m × 4m × 8m` 固定实验房的 P6-A ElementField，扩展为支持约 `40m～60m` 连续小型关卡的稀疏元素世界：法术可以在关卡任意合法位置创建 Water/Fire Chunk，玩家附近 Chunk 高频模拟与渲染，远处非空 Chunk 在本次 Play Session 内休眠并保留数据，玩家返回后继续模拟。

**Architecture：** 保留 `ElementFieldRuntime` 和现有固定数组 Simulator 作为 P6-A 回归基线，不让 `ElementFieldLabRoot` 跟随玩家。新增固定世界坐标的 `ElementWorldRuntime`：用全局 Cell/Chunk 坐标和稀疏 `Dictionary<ElementChunkKey, ElementWorldChunk>` 保存真正出现过元素的 Chunk；玩家只决定 Active/Sleep 集合，不改变世界 Origin。新 World Simulator 以稳定 Snapshot + Delta 处理跨 Chunk Reaction/Down Flow/Lateral Flow/Fire Decay；Projectile、Exposure、Water/Fire Rendering 通过新接口接入，Gameplay 不依赖 Rendering。

**Tech Stack：** Unity 6.3、C#、URP 17.3、NUnit EditMode Tests、`ScriptableObject`、稀疏 Chunk Dictionary、固定 `10 Hz` Tick、预分配工作缓冲、NonAlloc Physics、动态 Chunk Mesh、共享三层 `ParticleSystem`、Unity Profiler。

## Global Constraints

- 玩家职业只保留 `WizardPlayer`；Warrior/Archer 不进入当前 Demo 玩家流程。
- 当前元素范围只包含 Water/Fire；Sticky/Poison 属于 Demo 完整后扩展项。
- 世界坐标系固定，严禁把元素世界 Root Parent 到玩家或逐帧移动 World Origin。
- `CellSize = 0.25m`，`ChunkSize = 8`，一个 Chunk 为 `2m × 2m × 2m`；Chunk Key 允许负坐标。
- 玩家是主要 Interest Point；法术写入点也可以激活命中 Chunk。
- Active Chunk 按 `10 Hz` 模拟；Sleep Chunk 保留非空 Cell，但不模拟、不 Exposure、不渲染。
- 第一版只保证同一次 Play Session 内持久化，不实现磁盘存档、联网同步或跨 Scene 保存。
- 非空 Chunk 不因距离被丢弃；空且休眠超过 Grace Period 的 Chunk才可以回收。
- 到达 `MaximumResidentChunks` 后拒绝创建新 Chunk，并通过限频 `GameLog.Warn` 暴露错误，不能静默覆盖旧元素。
- 不为 Cell 创建 GameObject、Transform 或 Collider；一个可见 Water Chunk最多一个 Mesh GameObject，Fire 继续复用全世界三层 ParticleSystem。
- `Game.ElementField` 依赖 `Game.Core + Game.Combat`；`Game.Rendering` 只读 Element World；`Game.Combat` 不反向依赖 ElementField。
- 热路径禁止 LINQ、Closure、Boxing 和每 Tick `new`；Dictionary 扩容必须在初始化 Capacity 预算内完成。
- 保留现有固定 `ElementFieldRuntime` Tests 和 SampleScene Gate，所有新增改动不得破坏 P6-A。
- 每完成一个 Task，更新 `Assets/_Project/Docs/2026-07-15 P6有限元素场完整解析.md`，写明基础原理、脚本职责、架构集成、公式、测试、踩坑和 Editor Gate。

## 本计划不包含的下一子项目

本计划只完成“连续关卡可以承载元素互动”的世界基础。其后单独制定灰盒关卡与流程计划，包括：S 形 `40m～60m` 地图、三个战斗区、Encounter Gate、最终精英、出口和通关 UI。这样可以先证明任意位置 Cell 正常，再搭关卡，避免地编完成后因 Runtime 重构返工。

## 方案比较与最终选择

| 方案 | 优点 | 主要问题 | 结论 |
|---|---|---|---|
| 让现有 `ElementFieldLabRoot` 跟随玩家 | 改动看似最少 | Origin 改变导致旧 Cell、Solid、Mesh 和世界位置错位 | 禁止 |
| 扩大单个连续数组覆盖整张关卡 | 可复用现有 Simulator | 大量 Empty Cell 常驻；每 Tick 全量扫描；尺寸迅速超过 131K | 不采用 |
| 多个手工固定 Field 拼接 | 容易理解 | Field 边界阻断水流和反应；关卡作者负担高 | 仅可作临时原型 |
| 稀疏世界 Chunk + 玩家 Active Set | 任意命中点按需创建；跨区持久；规模由真实互动控制 | 需要新增跨 Chunk Solver 和 Renderer 生命周期 | 最终采用 |
