# 元素世界 Phase D：局部稳定流体表示实施计划

> **For agentic workers:** 使用 `superpowers:executing-plans` 在当前工作区连续执行；行为改动遵循 `superpowers:test-driven-development`。本阶段未授权 SubAgent，按 Phase Gate 向用户汇报。

**Goal:** 在当前电脑、1920×1080、60 FPS 的约束下，让同一战场中的稳定 Water、Poison、Sticky 不再永久占用与活动液体相同数量的 GPU particle slot；普通液体写入在有限压力基准内持续成功，并保留物质量、材质身份、角色接触、元素反应与重新流动能力。

**Architecture:** 继续使用单一 GPU PBF Pool 表达正在流动的液体，继续使用 Phase C 的 RAM Cell Archive 表达低成本物质量。容量压力出现时，Archive Kernel 允许选择 Active Region 内已经 `Solver-Sleeping` 的粒子；Archive Store 记录 Chunk 是远程 `Cold` 还是本地 `Dormant`。`Dormant` 数据继续承担 Gameplay Authority，并由低成本 Cell Proxy 表现；新的写入、火焰反应或显式扰动请求唤醒对应 Chunk。恢复采用固定 particle budget 分批准备，并在完整 Chunk 发布前维持 Archive 单一权威，避免 Amount 重复。统一的 8 GMU/particle 只负责数量换算，不承担动态 LOD。

**Tech Stack:** Unity 6.3、C#、HLSL Compute Shader、GPU PBF、`AsyncGPUReadback`、URP `RenderMeshInstanced`、`ProfilerMarker`、NUnit、Windows Development Build。

**Spec:** 本计划兼作本阶段唯一设计文档；项目规则不创建单独 spec。用户已在上一 Phase 汇报后确认继续，并要求以 Phase 为确认节点。

## 设计取舍

- 不通过运行时提高 GMU/particle 来省容量。该做法会同时改变 PBF 质量、密度采样和接触粒度，不能保证视觉与玩法不变。
- 不删除最旧液体，也不把失败写入当作成功。有限内存仍有 Archive 上限；上限到达时保留原 GPU 权威并暴露诊断。
- 本阶段以 Chunk 为休眠/唤醒单位。它比逐粒子压缩状态简单，能复用 Phase C 的事务边界；代价是一个 Cell 受到扰动时会唤醒同 Chunk 的稳定液体。
- `Dormant` 的静态表现允许退化为 Cell 级代理；唤醒后仍由原 GPU Marching Cubes Surface 接管。两者的切换由权威版本驱动，不改变 Gameplay Amount。

## Rollback

关闭 `EnableLocalDormancy` 后，Kernel 只归档 Warm Region 外粒子，Runtime 恢复 Phase C 行为；Dormant Renderer 无数据时不提交 Draw。任何 Free/Alive 守恒、Amount 重复或 D3D11 Compute 错误都立即关闭该开关，不删除 Archive 数据或改回静默丢弃。
