# Arrow 敌人抛物线射击 Implementation Plan

> **For agentic workers:** 按 Task 顺序在当前会话内实施并逐项复核。项目禁止未经本次用户明确授权使用 SubAgent，因此本计划只允许 `superpowers:executing-plans` Inline Execution。Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不复制 Enemy AI、不破坏现有法师敌人直线施法的前提下，落地一个使用弓动画与 `Arrow` Prefab 的普通远程敌人；它在动画释放帧锁定“玩家世界位置 + 胸口高度”，计算受 `Physics.gravity` 影响的初速度，使理想抛物线经过该 `aimPoint`。

**Architecture:** `RangedEnemyController` 继续复用 `EnemyControllerBase`、`EnemyKiteState`、`EnemyRangedAttackState` 与 `SpellCaster`。新增显式的 `SpellAimMode` 作为 `Game.Character` Runtime Authoring 选项：已有 Prefab 缺省值为 `Direct`，Arrow 敌人配置为 `BallisticToPoint`。纯数学类 `BallisticTrajectory` 只计算初速度和飞行时间；`SpellCaster` 仍是唯一负责 `Instantiate` 与 `ProjectileBase.Init` 的 Runtime Adapter。Arrow 的伤害、速度与重力来自 `SpellDefinition + WandLoadout`，Enemy 的移动、感知、射程与冷却继续来自 `EnemyDefinition`。

**Tech Stack:** Unity 6.3、C#、ScriptableObject、Rigidbody、`Physics.gravity`、Animator `normalizedTime`、Game.Character / Game.Skills / Game.Combat asmdef、NUnit EditMode Tests。

**Design:** 用户已确认“抛物线 Arrow，瞄准点为玩家世界位置加胸口高度，并保证轨迹经过 aimPoint”。本计划把该设计具体化；不另建重复 spec。

## Global Constraints

- 不新增 `ArcherEnemyController`：普通弓箭敌人是现有 `RangedEnemyController` 的一套数据与 Prefab 配置。
- 不删除或弱化玩家 `ArcherController`、玩家弓攻击、Enemy 远程框架；它们属于后续变形法术和普通弓箭敌人的保留能力。
- 法师敌人及玩家法术继续使用 `Direct`；只有显式配置 `BallisticToPoint` 的根层 `ForwardProjectile` 才求解抛物线。
- 轨迹目标在动画释放帧锁定。玩家释放后移动可以躲箭，不做持续追踪，也不做移动目标提前量预测。
- “保证命中 aimPoint”指无碰撞、重力恒定条件下，连续运动学方程严格经过目标点；Unity PhysX 用离散 `FixedUpdate` 积分，实际碰撞仍受 Collider 大小、固定时间步和途中障碍影响，不宣称逐浮点位完全重合。
- `BaseSpeed` 在弹道模式中解释为“名义水平/路程速度，用来决定飞行时间”，而非强制保持最终初速度模长；为补偿重力，实际初速度的 Y 分量会提高。
- Trigger Payload 在命中点继续使用 `Direct`，不继承根层旧的玩家胸口目标，避免后续 Payload 反向飞向已经过期的位置。
- `Update`、Enemy FSM 与 Projectile 热路径禁止 LINQ、装箱、临时数组和每帧对象分配；弹道求解只发生在离散施放时。
- 不手工创建 `.meta`。新 C#、测试、ScriptableObject、Prefab 和文档首次导入时由 Unity 生成 GUID；涉及资产引用时按“先创建叶子资产并导入，再读取 GUID 创建组合资产”的顺序执行。
- 复用已有 `Arrow.prefab`、Bow 模型和 `BowHero.controller`，不需要用户额外提供模型、动画、材质、VFX、音频或字体。
- 保留并避开用户已有 dirty 文件，尤其是 `SwordEnemy_Base.prefab` 与 `MaterialCatalog_Default.asset`；不自动提交 Git。

## Runtime Call Chain

```text
EnemyRangedAttackState 到达 ArrowSpawnTime
  -> RangedEnemyController.CastSelectedProgram()
  -> aimPoint = target.position + Vector3.up * _aimHeightOffset
  -> SpellCaster.CastProgram(..., _aimMode)
  -> CastEvaluator.Evaluate(...) 生成 EmitCommand
  -> SpellCaster.SpawnForwardProjectile(...)
  -> Direct: velocity = direction * speed
     BallisticToPoint + UseGravity:
       flightTime = max(distance / nominalSpeed, minimumFlightTime)
       velocity = (target - origin - 0.5 * gravity * flightTime^2) / flightTime
  -> ProjectileBase.Init(..., velocity, useGravity: true)
  -> Rigidbody 受 Physics.gravity 积分
  -> OnCollisionEnter -> IDamageable.ReceiveHit(...)
```

## Ballistic Formula and Boundary Contract

连续位移公式为：

```text
target = origin + velocity * t + 0.5 * gravity * t^2
```

把初速度移到等式左侧可得：

```text
velocity = (target - origin - 0.5 * gravity * t^2) / t
```

实现采用：

- `distance = Vector3.Distance(origin, target)`。
- `t = Mathf.Max(distance / nominalSpeed, minimumFlightTime)`。
- `nominalSpeed <= epsilon`、输入包含 `NaN/Infinity` 或计算结果无效时返回 `false`，调用方降级为已有 `Direct` 速度，避免生成带 `NaN` 的 Rigidbody。
- 起点和终点几乎重合时返回 `false`，因为不存在有意义的射击方向。
- 默认 `minimumFlightTime = 0.1s`，防止极近距离导致除以接近零的时间。

这套“指定时间反解初速度”的选择优点是目标可达且没有固定速度弹道的判别式无解区间；代价是近距离或高低差很大时实际初速度模长可能偏离 Authoring 的 `BaseSpeed`。固定速度双角度解会更符合真实弓力，但远距离/高目标可能无解，不符合当前“保证经过 aimPoint”的需求，因此本期不采用。

## Rollback and Failure Isolation

- Runtime 回滚：把 Arrow Prefab `_aimMode` 改回 `Direct`，即可绕过弹道求解而保留 Enemy、Spell Program 与 Arrow 内容。
- 内容回滚：从 Scene 移除 `ArrowEnemy_Base`，不会影响 Wizard Enemy；新资产均为独立路径。
- 若 Wizard 火球变弧线：先检查枚举 0 是否仍为 `Direct`、MagicEnemy Prefab 是否被误写为 1，再检查 `CastProgram` 默认参数。
- 若轨迹经过目标但没有伤害：弹道层已正确，继续检查 Arrow Collider、玩家 Collider、TeamId、`ProjectileBase.OnCollisionEnter` 与 Layer Collision Matrix。
- 若箭完全不生成：检查 Program 顺序/`BaseDraws`、Spell Prefab、Animator 状态名与 `ArrowSpawnTime`，不要先调整弹道公式。
- 若箭出生即消失：检查 `_castOrigin` 是否位于施法者 Collider 内，以及 `ProjectileBase.Init` 是否收到正确 `casterCollider`。
- 删除新增资产时只删除本计划列出的精确文件；绝不对目录执行递归删除，也不回滚用户已有 dirty 改动。

- 实际修改/新增文件。
- `git diff --check` 与静态调用点检查结果。
- Unity Compilation 状态。
- Focused EditMode、Assembly EditMode 的真实通过/失败/跳过数量。
- 实际完成的 PlayMode/Scene Playthrough 项；未执行的明确标为“需用户在 Editor 验证”。
- Profiler 是否实测；未实测不得宣称 zero `GC Alloc`。
- 用户需要执行的精确 Editor 操作与推荐调参顺序。
