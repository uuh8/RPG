# P1 状态可视化 2.0：URP 角色状态材质系统详细实施计划

> **执行规则：** 本计划默认由当前主 Agent 在本地 `main` 直接执行。未经用户对当前任务的明确批准，禁止使用 SubAgent；不创建 worktree 或额外分支。所有任务使用复选框追踪，并在每个 Unity Editor Gate 得到用户确认后再继续。

**目标：** 在 Unity 6.3 URP 中实现一套由 `StatusController` 强度连续驱动的角色状态材质系统：Burning 使用 Object Space 流动 Noise、灼烧变色与 HDR Emission，Wet 使用 Smoothness、轻微冷色与 Fresnel 水膜；先在 WizardPlayer 与 MagicEnemy 验证，再推广到全部角色。

**架构：** `Game.Combat.StatusController` 继续拥有 Gameplay 状态并发布现有 `StatusChangedEvent`；`Game.Rendering.StatusMaterialController` 作为只读表现桥订阅事件、平滑强度并通过复用的 `MaterialPropertyBlock` 写入共享角色材质。统一的 URP Lit Shader Graph 保留原角色 PBR 输入，在同一个 Fragment 表面计算中组合 Burning 与 Wet；Gameplay 不引用 Shader，Rendering 不修改状态。

**技术栈：** Unity 6.3、URP 17.3、Shader Graph Universal Lit、HLSL Custom Function、`MaterialPropertyBlock`、`EventBus<T>`、NUnit、Unity Test Framework、Frame Debugger、Unity Profiler。

## 0. 已确认的产品与学习决策

### 0.1 第一版范围

- 正式实现 Burning 与 Wet。
- C# 桥和 Shader Property 预留 Poisoned、Sticky，但第一版不计算它们的视觉效果。
- 先完成 WizardPlayer + MagicEnemy，得到用户验证后再推广 Warrior、Archer、SwordEnemy 等角色。
- 保留现有 `OnFire` Particle VFX：外围火焰由 VFX 表达，角色表面热纹由 Shader 表达。
- 不制作体素、流体、水滴模拟、全屏 Renderer Feature 或完整手写 URP 光照。

### 0.2 Burning 视觉目标

```text
低强度：少量暗红热斑
中强度：Object Space Noise 形成向上流动的炽热纹路
高强度：发光区域扩大，HDR Emission 增强
强度归零：恢复原角色表面
```

Object Space 是第一版锁定方案。它让 Noise 随角色移动，不固定在世界中；若模块化身体部件出现无法接受的接缝，才单独设计“角色根节点相对坐标”升级，不在第一版提前增加每帧根位置上传。

### 0.3 Wet 视觉目标

```text
低强度：Smoothness 轻微提高
中强度：表面出现轻微冷色调与更集中的高光
高强度：Fresnel 边缘水膜更明显，但保留原贴图可读性
强度归零：恢复原 PBR 参数
```

### 0.4 多状态规则

- Shader 独立读取 `_BurningIntensity` 与 `_WetIntensity`。
- Shader 不实现第二套“Wet 熄灭 Burning”Gameplay 规则。
- `StatusController` 已负责 Wet 加速 Burning 衰减；Shader 只显示最新强度。
- Burning 修改表面颜色与 Emission；Wet 修改冷色混合、Smoothness 与 Fresnel 边缘，两者可短暂共存。
- `CharacterCombatFeedback` 继续只负责 `_BaseColor` 受击闪红；状态桥必须先 `GetPropertyBlock`，只覆盖自己的四个 Float，再 `SetPropertyBlock`，不可清掉其他组件写入的字段。

## 1. 初学者必须先理解的渲染链路

### 1.1 URP、Shader、Material、Renderer 的关系

```text
URP
  组织一帧中的相机、灯光、阴影、不透明物体、透明物体和后处理

Shader
  定义顶点与像素如何计算

Material
  保存某个 Shader 使用的贴图、颜色和数值

Renderer / SkinnedMeshRenderer
  把 Mesh 与 Material 交给 URP 绘制
```

P1 不从零重写 URP。`SG_CharacterStatusLit` 使用 Shader Graph 的 Universal Lit Target，URP 继续负责灯光、阴影、Fog、GI 和 PBR 光照；P1 只计算 Base Color、Normal、Metallic、Smoothness、Occlusion、Emission 等表面输入。

### 1.2 Shader Graph 与 HLSL 的关系

Shader Graph 节点最终也会生成 Shader/HLSL。P1 先用节点看懂 Wet Fresnel 的每一步，再把完全相同的小公式写进 `StatusFresnel.hlsl`，通过 Custom Function 节点调用。目的不是优化，而是建立“数学公式 ↔ 节点 ↔ HLSL”对应关系。

### 1.3 CPU 到 GPU 的数据路径

```text
StatusController.Intensity（CPU Gameplay，0~100）
-> StatusChangedEvent
-> StatusMaterialController（CPU Rendering Bridge）
-> 归一化与平滑（0~1）
-> MaterialPropertyBlock
-> Shader Property（GPU）
-> Fragment 表面计算
-> URP Lit 光照
-> 屏幕像素
```

- [x] **Step 5：实现 StatusMaterialController**

实现时保留下列教学注释，不得删成无注释版本：

```csharp
using System.Collections.Generic;
using Game.Combat;
using Game.Core;
using UnityEngine;

namespace Game.Rendering
{
    /// <summary>
    /// 把 Combat 状态强度转换为角色 Shader 参数的只读表现桥。
    /// Gameplay 仍由 StatusController 决定；本组件只订阅事件并写 MaterialPropertyBlock，
    /// 不修改状态、不创建材质实例，也不让 Combat 反向依赖 Rendering。
    /// </summary>
    [DisallowMultipleComponent]
    [RequireComponent(typeof(StatusController))]
    public sealed class StatusMaterialController : MonoBehaviour
    {
        // Property Reference 必须和 Shader Graph Blackboard 完全一致。
        // 使用 PropertyToID 只在类型初始化时做一次字符串哈希，避免热路径重复查找。
        private static readonly int BurningId = Shader.PropertyToID("_BurningIntensity");
        private static readonly int WetId = Shader.PropertyToID("_WetIntensity");
        private static readonly int PoisonedId = Shader.PropertyToID("_PoisonedIntensity");
        private static readonly int StickyId = Shader.PropertyToID("_StickyIntensity");
        private const float SettleEpsilonSqr = 0.00000001f;

        [Header("目标 Renderer")]
        [Tooltip("留空时会在 Awake 自动收集使用状态 Shader 的子 Renderer；也可手动指定以排除不需要状态表现的部件。")]
        [SerializeField] private Renderer[] _targetRenderers;

        [Header("视觉响应")]
        [Tooltip("Shader 显示强度每秒最多变化多少。4 表示从 0 到 1 最快约 0.25 秒。")]
        [SerializeField, Min(0.01f)] private float _responseSpeed = 4f;

        private StatusController _statusController;
        private MaterialPropertyBlock _propertyBlock;
        private int _targetId;
        private Vector4 _current;
        private Vector4 _target;
        private bool _isTransitioning;

        public float BurningVisualIntensity => _current.x;
        public float WetVisualIntensity => _current.y;
        public float PoisonedVisualIntensity => _current.z;
        public float StickyVisualIntensity => _current.w;

        private void Awake()
        {
            _targetId = gameObject.GetInstanceID();
            _statusController = GetComponent<StatusController>();
            _propertyBlock = new MaterialPropertyBlock();
            CacheCompatibleRenderers();
        }

        private void OnEnable()
        {
            EventBus<StatusChangedEvent>.Subscribe(OnStatusChanged);

            // 对象池重新启用或组件重新打开时，事件可能已经发生过。
            // 因此主动读取一次权威 Gameplay 状态，避免等待下一次事件才恢复画面。
            SyncFromStatusController(snapImmediately: true);
        }

        private void OnDisable()
        {
            EventBus<StatusChangedEvent>.Unsubscribe(OnStatusChanged);

            // 清零可避免对象池中的角色下次被复用时短暂显示上一次的状态。
            _target = Vector4.zero;
            _current = Vector4.zero;
            _isTransitioning = false;
            ApplyPropertyBlock();
        }

        private void Update()
        {
            Tick(Time.deltaTime);
        }

        private void OnStatusChanged(StatusChangedEvent e)
        {
            if (e.TargetId != _targetId)
                return;

            float normalized = e.IsActive ? Normalize(e.Intensity) : 0f;
            switch (e.Kind)
            {
                case StatusKind.Burning: _target.x = normalized; break;
                case StatusKind.Wet: _target.y = normalized; break;
                case StatusKind.Poisoned: _target.z = normalized; break;
                case StatusKind.Sticky: _target.w = normalized; break;
            }

            _isTransitioning = true;
        }

        private void Tick(float deltaTime)
        {
            if (!_isTransitioning || deltaTime <= 0f)
                return;

            float maxDelta = Mathf.Max(0.01f, _responseSpeed) * deltaTime;
            // Vector4 是值类型，但这里仍避免在热路径出现容易误读的 new 写法；
            // 从当前快照复制后逐通道推进，不产生托管堆 GC Alloc。
            Vector4 next = _current;
            next.x = Mathf.MoveTowards(_current.x, _target.x, maxDelta);
            next.y = Mathf.MoveTowards(_current.y, _target.y, maxDelta);
            next.z = Mathf.MoveTowards(_current.z, _target.z, maxDelta);
            next.w = Mathf.MoveTowards(_current.w, _target.w, maxDelta);

            if ((next - _target).sqrMagnitude <= SettleEpsilonSqr)
            {
                next = _target;
                _isTransitioning = false;
            }

            if ((next - _current).sqrMagnitude <= SettleEpsilonSqr)
                return;

            _current = next;
            ApplyPropertyBlock();
        }

        private void SyncFromStatusController(bool snapImmediately)
        {
            if (_statusController == null)
                return;

            _target = new Vector4(
                Normalize(_statusController.GetIntensity(StatusKind.Burning)),
                Normalize(_statusController.GetIntensity(StatusKind.Wet)),
                Normalize(_statusController.GetIntensity(StatusKind.Poisoned)),
                Normalize(_statusController.GetIntensity(StatusKind.Sticky)));

            if (snapImmediately)
            {
                _current = _target;
                _isTransitioning = false;
                ApplyPropertyBlock();
            }
            else
            {
                _isTransitioning = true;
            }
        }

        private void ApplyPropertyBlock()
        {
            if (_propertyBlock == null || _targetRenderers == null)
                return;

            for (int i = 0; i < _targetRenderers.Length; i++)
            {
                Renderer targetRenderer = _targetRenderers[i];
                if (targetRenderer == null)
                    continue;

                // GetPropertyBlock 先取回受击闪红等其他系统已经写入的字段。
                // 随后只覆盖状态参数，避免 SetPropertyBlock 清掉 _BaseColor。
                targetRenderer.GetPropertyBlock(_propertyBlock);
                _propertyBlock.SetFloat(BurningId, _current.x);
                _propertyBlock.SetFloat(WetId, _current.y);
                _propertyBlock.SetFloat(PoisonedId, _current.z);
                _propertyBlock.SetFloat(StickyId, _current.w);
                targetRenderer.SetPropertyBlock(_propertyBlock);
            }
        }

        private void CacheCompatibleRenderers()
        {
            if (_targetRenderers != null && _targetRenderers.Length > 0)
                return;

            // Awake 中的一次性数组/List 分配可接受；禁止把这段扫描放进 Update。
            Renderer[] candidates = GetComponentsInChildren<Renderer>(includeInactive: true);
            var compatible = new List<Renderer>(candidates.Length);
            for (int i = 0; i < candidates.Length; i++)
            {
                Renderer candidate = candidates[i];
                if (candidate != null && SupportsStatusShader(candidate))
                    compatible.Add(candidate);
            }

            _targetRenderers = compatible.ToArray();
            if (_targetRenderers.Length == 0)
                GameLog.Warn("StatusMaterialController 没有找到支持状态参数的 Renderer", "Rendering");
        }

        private static bool SupportsStatusShader(Renderer targetRenderer)
        {
            // sharedMaterials 只在初始化扫描时读取，不使用 renderer.material，避免创建材质实例。
            Material[] materials = targetRenderer.sharedMaterials;
            for (int i = 0; i < materials.Length; i++)
            {
                Material material = materials[i];
                if (material != null && material.HasProperty(BurningId) && material.HasProperty(WetId))
                    return true;
            }

            return false;
        }

        private static float Normalize(float statusIntensity)
        {
```

## Task 3：在 Shader Graph 中实现 Burning

**Modify:** `SG_CharacterStatusLit.shadergraph`

**Produces:** `_BurningIntensity` 连续控制 Object Space 流动火纹、表面灼烧色和 HDR Emission。

- [x] **Step 1：增加 Burning Blackboard 属性**

| Display Name | Type | Reference | 建议默认值 |
|---|---|---|---|
| Burn Noise Scale | Float | `_BurnNoiseScale` | 3 |
| Burn Flow Speed | Float | `_BurnFlowSpeed` | 0.6 |
| Burn Mask Softness | Float Range 0.01–0.25 | `_BurnMaskSoftness` | 0.08 |
| Burn Surface Color | Color | `_BurnSurfaceColor` | 深暗红 |
| Burn Emission Color | Color HDR | `_BurnEmissionColor` | 橙红，HDR Intensity 约 3–5 |

- [x] **Step 2：构造 Object Space 流动坐标**

节点：

```text
Position(Object) -> Split

Horizontal = X + Z × 0.37
Vertical = Y + Time × _BurnFlowSpeed

Combine(Horizontal, Vertical)
-> Multiply(_BurnNoiseScale)
-> BurningNoiseUV
```

方向说明：理论上的相位移动还会受到导入模型 Object Space 轴约定影响。当前角色资源经 Game View 验证后，使用 `Y + Time × Speed` 才表现为视觉向上流动，因此以项目实测方向为准。

- [x] **Step 3：从 Noise 生成随强度扩大的遮罩**

```text
Simple Noise(UV=BurningNoiseUV, Scale=1)
-> NoiseValue 0~1

BurnVisualIntensity = Pow(Saturate(_BurningIntensity), 0.6)
Threshold = Lerp(0.95, 0.35, BurnVisualIntensity)
Lower = Threshold - _BurnMaskSoftness
Upper = Threshold + _BurnMaskSoftness
Mask = Smoothstep(Lower, Upper, NoiseValue)
FinalBurnMask = Mask × BurnVisualIntensity
```

`Smoothstep` 相比 Step 有柔和过渡，避免火纹边缘严重锯齿。指数小于 1 的 `Power` 曲线会抬高 0~0.5 的视觉响应，使低强度状态也清晰可读，同时保持 0 和 1 两个端点不变；最后再次乘视觉强度，保证强度 0 时绝对没有残留。

- [x] **Step 4：混合表面灼烧色**

```text
BurnedColor = Lerp(
    OriginalBaseColor,
    OriginalBaseColor × _BurnSurfaceColor,
    Saturate(FinalBurnMask × 0.75)

```

不要直接把 Base Color 替换成纯红色，否则会丢失角色原贴图细节。

```text

FinalEmission = OriginalEmission + BurnEmission
```

连接：`BurnedColor -> Base Color`，`FinalEmission -> Emission`。

## Task 4：在 Shader Graph 中实现 Wet

**Modify:** `SG_CharacterStatusLit.shadergraph`

**Produces:** `_WetIntensity` 控制 Smoothness、轻微冷色和 Fresnel 边缘水膜。

- [x] **Step 1：增加 Wet Blackboard 属性**

| Display Name | Type | Reference | 建议默认值 |
|---|---|---|---|
| Wet Smoothness | Float Range 0–1 | `_WetSmoothness` | 0.92 |
| Wet Fresnel Power | Float Range 0.5–8 | `_WetFresnelPower` | 4 |
| Wet Tint Color | Color | `_WetTintColor` | 很浅的蓝青色 |
| Wet Tint Strength | Float Range 0–0.3 | `_WetTintStrength` | 0.08 |
| Wet Edge Color | Color | `_WetEdgeColor` | 浅蓝灰 |
| Wet Edge Strength | Float Range 0–0.3 | `_WetEdgeStrength` | 0.12 |

- [x] **Step 2：用 Shader Graph 节点计算 Fresnel**

必须保证两个方向都在 World Space：

```text
Normal Vector(World) -> Normalize ----\
                                      Dot Product
View Direction(World) -> Normalize --/
-> Saturate
-> One Minus
-> Power(_WetFresnelPower)
-> Fresnel
```

数学解释：正对摄像机时 `dot(N,V)` 接近 1，One Minus 后接近 0；轮廓处点积接近 0，One Minus 后接近 1，因此边缘遮罩更亮。

- [x] **Step 3：计算 Wet Smoothness**

```text
BaseSmoothness = MetallicGlossMap.A × _Smoothness
WetTarget = Max(BaseSmoothness, _WetSmoothness)
FinalSmoothness = Lerp(BaseSmoothness, WetTarget, _WetIntensity)
```

使用 Max 避免原本非常光滑的金属装备在 Wet 后反而变粗糙。

- [x] **Step 4：计算冷色与边缘水膜**

```text
TintAmount = _WetIntensity × _WetTintStrength
WetTintedColor = Lerp(BurnedColor, BurnedColor × _WetTintColor, TintAmount)

WetEdgeMask = Fresnel × _WetIntensity × _WetEdgeStrength
FinalBaseColor = WetTintedColor + _WetEdgeColor × WetEdgeMask
```

WetEdge 不接 Emission，避免水膜像霓虹灯一样自己发光。

- [x] **Step 5：连接最终 Lit 输入**

```text
FinalBaseColor -> Base Color
FinalSmoothness -> Smoothness
FinalEmission（仍来自 Burning + 原 Emission）-> Emission
```

```text

Combined：Burning=0.6, Wet=0.7
```

## Task 5：用 HLSL Custom Function 重写 Wet Fresnel

**Files:**

- Create: `Assets/_Project/Shader/StatusFresnel.hlsl`（按项目实际 Shader 目录落地）
- Modify in Editor: `SG_CharacterStatusLit.shadergraph`

**Produces:** 节点版与 HLSL 版同公式对照；最终 Graph 使用 HLSL Custom Function 输出。

- [x] **Step 1：创建带教学注释的 HLSL 文件**

```hlsl
#ifndef GAME_STATUS_FRESNEL_INCLUDED
#define GAME_STATUS_FRESNEL_INCLUDED

// Shader Graph 的 Custom Function 使用“函数名_精度后缀”规则。
// 当前 Graph 使用 Float 精度，因此函数名以 _float 结尾。
void StatusFresnel_float(
    float3 NormalWS,
    float3 ViewDirectionWS,
    float Power,
    out float Fresnel)
{
    // Dot Product 只有在两个方向位于同一 Coordinate Space 时才有几何意义。
    // 调用者必须传入 World Space 的法线与视线方向。
    float3 normal = normalize(NormalWS);
    float3 viewDirection = normalize(ViewDirectionWS);

    // 正对摄像机时 N·V 接近 1，轮廓处接近 0。
    // saturate 把浮点误差产生的越界结果限制到 0~1。
    float ndotv = saturate(dot(normal, viewDirection));

    // One Minus 把“正面亮”反转成“边缘亮”。
    // Power 越大，亮边越窄；max 防止 0 或负指数造成不稳定结果。
    Fresnel = pow(1.0 - ndotv, max(Power, 0.0001));
}

#endif
```

```text

Name = StatusFresnel
Precision = Float

Inputs:
NormalWS        Vector3
ViewDirectionWS Vector3
Power           Float

Output:
Fresnel         Float
```

连接 World Space Normal、World Space View Direction 和 `_WetFresnelPower`。

临时保留两个输出 Preview：

## 4. 常见故障与 Debug 顺序

### 4.1 材质变粉

按顺序检查：

1. Shader Graph Target 是否为 Universal Lit。
2. Console 是否有 Shader 编译错误。
3. HLSL Custom Function 名称是否为 `StatusFresnel`，文件内函数是否为 `StatusFresnel_float`。
4. HLSL 输入输出名称、类型是否与节点一致。
5. URP Asset 是否正确绑定。

### 4.2 C# 状态变化但 Shader 没反应

按链路排查：

```text
StatusController.GetIntensity
-> StatusChangedEvent.TargetId/Kind/Intensity
-> StatusMaterialController.Target
-> Current 是否 MoveTowards
-> Renderer 是否被缓存
-> MPB 是否存在对应 Float
-> Shader Graph Property Reference 是否精确匹配
```

重点：Display Name 写对但 Reference 写错，C# 仍然无法设置。

### 4.3 受击闪红后状态消失

检查两个组件是否都执行：

```csharp
renderer.GetPropertyBlock(block);
// 只修改自己的字段
renderer.SetPropertyBlock(block);
```

任何一方创建空 Block 后直接 Set，都会清掉另一方字段。

### 4.4 角色移动时火纹漂浮

检查 Burning 坐标是否误用了 World Position。第一版必须使用 Object Position；如 Graph 中 Transform 节点配置错误，也可能得到 World Space。

### 4.5 多部件火纹接缝明显

先确认各 Renderer 是否使用同一个 `_BurnNoiseScale`、FlowSpeed 和状态强度。若参数一致仍明显断层，记录各 SkinnedMeshRenderer 的局部 Transform；这意味着 Object Space 不统一，需要单独设计根节点相对坐标，不用随意调 Noise 掩盖架构问题。

### 4.6 Wet 看起来只是变蓝

- 降低 `_WetTintStrength`。
- 暂时把 Tint 设为白色，只观察 Smoothness 与 Fresnel。
- 移动灯光和摄像机；没有反射环境或高光时，Smoothness 变化可能不明显。
- 检查 Normal 与 View Direction 是否都为 World Space。

### 4.7 Emission 很亮但没有辉光

Emission 与 Bloom 是两件事。检查 Global Volume Bloom、相机 Post Processing、HDR Color 强度和 Bloom Threshold。

### 4.8 MPB 没有生成材质副本但 Batching 下降

这是可能发生的真实 trade-off。使用 Frame Debugger 确认 SRP Batcher 状态；不要改成 `renderer.material` 逃避问题。第一版以正确性和无材质副本为主，记录 10 角色数据后再决定是否需要更高级的 instancing/renderer 方案。
