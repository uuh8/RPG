# Sticky 粘液材料与纯控制法术 Implementation Plan

## 2026-08-26 修订：Sticky UI、Projectile 与 Water 转化回归修复

本节覆盖下方旧版 `DiluteGoo` 与“资源只能手工配置”的约束；稳定枚举数值仍保持不变。

### 已确认根因

1. `P7_DemoRun` 的 `StickySlot/StatusIconView` 把 `_icon`、`_percentageText` 引到了槽位之外的其他 UGUI 组件，导致 Runtime 正在更新错误对象，而画面中的 Sticky 槽一直保留白块与 `0%`。
2. `PF_ElementStickyProjectile` 把 `M_ElementSticky_PBF` 交给普通 Sphere `MeshRenderer`。该材质的 `Liquid Procedural` Shader 只接受 GPU Surface Renderer 提供的 `StructuredBuffer`，普通 Mesh 没有这份顶点数据，因此只剩 Collider 可用。
3. 旧 `DiluteGoo` 只消费 Sticky、完全保留 Water，违反本次确认的世界材料语义。

### 修订后的产品语义

- 世界中 `Water + Sticky` 改为 `AbsorbWater`：Sticky 是接触催化条件，不被该反应消耗；有限数量 Water 粒子在原位置转换为 Sticky 粒子。
- 转换按 `1 Water particle -> 1 Sticky particle` 保持 GPU 粒子数量守恒，不通过 Spawn 凭空扩容，也不占用 Free Particle Pool。
- `WaterConvertPerSecond` 只控制转换速率；旧枚举序号 `3` 保留，避免 ScriptableObject/Event 持久化失效。
- 角色状态仍由 `CalculateWetCleanse` 独立处理：Wet 可以清洗角色身上的 Sticky，不与世界粒子转换互相复用。

### 性能、回滚与验证

- Reaction/Simulation 热路径继续使用预分配数组，无 LINQ、Closure 或逐帧 Managed Allocation。
- Conversion Dispatch 只在存在命令时执行；每条命令限制最大转换粒子数，避免全池无界工作。
- 若 GPU Contract 失败，可只回滚 `FluidConvertCommand + ConvertParticles`，不会影响 Projectile Deposit、角色 Wet Cleanse 或现有 Fire/Poison 反应。
- 验收必须同时观察 Water 粒子减少、Sticky 粒子增加、总 Alive Particle Count 不变，以及角色 Wet 清洗 Sticky 仍通过测试。

**Goal:** 在不重做现有 GPU PBF 与单 Surface Rendering 主链、不重新引入液体 LOD 的前提下，把预留的 `MaterialId.Sticky` 正式实现为琥珀色高黏度液体；提供 Sticky Orb 与场景 Initial Deposit 两种生成方式，实现环境接触固定减速 40%、离场后按 Sticky 强度逐渐恢复，并补齐 Water/Poison/Sticky Orb 的直接命中状态。

**Architecture:** Sticky 作为第四种正式 Material 接入既有数据驱动管线。`Game.Materials` 只定义稳定身份与宏观行为；`Game.ElementField` 负责 GPU PBF、Initial Deposit、Gameplay Occupancy、环境 Exposure 与世界材料反应；`Game.Combat` 负责状态、直接命中状态和最终移动倍率；`Game.Character` 只消费倍率；`Game.Rendering` 只读取 GPU Snapshot 并绘制琥珀色 Marching Cubes 表面。三个液体共用 Solver/Compute/Shader Contract，但拥有独立 Simulation Profile、Render Profile 与 Material。

**Tech Stack:** Unity 6.3、URP 17.3、C#、HLSL、Compute Shader、GPU PBF、Spatial Hash、Marching Cubes、ScriptableObject、Event/Impact Contract、NUnit EditMode Tests。

**Approved Product Semantics:**

- Sticky Orb 是纯控制法术：直接伤害为 0，直接命中 `Sticky +20`，落点生成 Sticky 流体。
- Water Orb 直接命中 `Wet +15`；Poison Orb 直接命中 `Poisoned +10`。墙壁/地面只生成对应流体。
- 站在环境 Sticky 中固定减速 40%；离开后减速率为 `40% × StickyIntensity / 100`，直至恢复。
- 玩家、普通近战敌人、普通远程敌人与 Wizard Boss 使用相同规则。
- Sticky + Fire：`IgniteGoo`，Sticky 被连续消耗并转化为 Fire。
- Sticky + Water：`DiluteGoo`，Water 作为溶剂，连续清除 Sticky，Water 不被消耗。
- Sticky + Poison：不生成第五种材料，允许共存并同时投射 Sticky/Poisoned。
- Sticky + Sticky：由 PBF 自然合并，不建立反应规则。
- 同时接触 Water 与 Fire 时，Water 清洗/抑制拥有更高优先级，避免同一份 Sticky 在同一 Tick 被两条反应重复消费。

## 设计基线与已核实事实

1. `MaterialId.Sticky = 4`、`StatusKind.Sticky = 3` 与 `Status_Sticky.asset` 已存在，但 Sticky 尚未加入 Material Catalog、GPU Liquid Profile、Status Projection、Initial Deposit 白名单和 Surface Renderer。
2. `Status_Sticky.asset` 已配置 `NaturalDecayPerSecond = 8`、`AffectsMoveSpeed = true`、`MaxMoveSpeedSlowRatio = 0.4`，现有倍率公式只支持按强度减速。
3. `ApplySustainedStatus` 已维护 `NaturalDecayHoldRemaining`。本轮把它作为短暂的 Sustained Contact Lease 使用；不再增加第二套环境接触计时器。
4. 玩家与 Wizard Boss 已消费 `MoveSpeedMultiplier`，普通敌人的 `EnemyControllerBase.MoveHorizontal` 尚未消费。
5. Water/Poison Projectile Prefab 当前只有 `ElementDepositOnImpact`，没有直接命中状态；`ProjectileImpactContext` 也未携带命中目标与来源。
6. Water/Poison 已共用一个 GPU PBF Runtime，并依靠 Material Id 区分参数、Gameplay Occupancy 与独立 Surface Renderer；Sticky 应沿用该模式。
7. 当前 `GpuLiquidSurfaceRenderer` 仍存在 `_debugForceOpaqueFragment` 诊断开关。Sticky 最终视觉验收前必须关闭诊断 Fragment，回到正常 PBR/Transparency 路径，否则只能看到纯色而看不到高光、深浅与表面细节。
8. 增加第三个 Surface Renderer 会增加一次 Density/Marching Cubes/Draw 成本；本轮以质量正确为先，通过 Profiler Gate 记录成本，不用 LOD 掩盖问题。

## 推荐初始参数

这些是第一轮 Editor 起点，不是硬编码常量；最终以 Game View 和 Profiler 为准。

### Sticky PBF Material Profile

| 参数 | Water | Poison | Sticky 起点 | 设计含义 |
|---|---:|---:|---:|---|
| Amount Units Per Particle | 8 | 4 | 4 | 保持小规模沉积轮廓细节 |
| Particle Mass | 1.0 | 1.1 | 1.2 | 提供更沉重的流动观感 |
| Rest Density | 1000 | 1050 | 1100 | 比 Poison 更紧实 |
| Viscosity | 0.08 | 0.32 | 0.65 | 显著减慢相邻粒子的相对速度 |
| Artificial Pressure | 0.001 | 0.0006 | 0.0004 | 减少把高黏液体撑散的倾向 |
| Cohesion Strength | 12 | 24 | 36 | 提高团聚、饱满与短颈连接 |
| Cohesion Rest Distance Ratio | 1.0 | 1.0 | 1.0 | 保持现有 Kernel 支持边界 |
| Maximum Cohesion Delta Speed | 0.20 | 0.16 | 0.12 | 限制 Cohesion 修正引发的抖动 |
| Sleep Density Error Threshold | 0.02 | 0.025 | 0.03 | 稳定后更容易进入 Sleeping |

不承诺真正的长丝拉伸。当前粒子 PBF + Marching Cubes 能稳定表现团块、缓慢铺展和短连接；真正的长丝需要额外的 Viscoelastic/Polymer Constraint，不在本轮范围。

### Sticky Surface Profile

- `Target Voxel Size = 0.10`
- `Maximum Resolution Per Axis = 96`
- `Bounds Padding = 0.30`
- `Iso Level = 500`
- `Maximum Triangle Count = 131072`
- `Use Anisotropy = true`
- `Crown Height Ratio = 0.75`
- `Crown Falloff = 1.25`
- `Crown Edge Neighbor Count = 4`
- `Crown Interior Neighbor Count = 12`

Sticky 的“厚”首先来自 PBF 粒子团聚、Cohesion 和 Marching Surface，而不是把顶点压成贴地薄片。`Crown` 只负责风格化凸起，不能代替体积。

### Sticky Material

- 深部：深琥珀/棕橙；浅部：金黄色；Fresnel：暖金色。
- `Shallow Alpha ≈ 0.55`、`Deep Alpha ≈ 0.85`、`Global Alpha ≈ 0.95`。
- `Smoothness ≈ 0.90`。
- Wave Speed 约为 Water 的 15%～25%，Wave Normal Strength 约 `0.10～0.15`。
- Foam Strength 约 `0.10～0.20`，只保留少量边缘亮带，不形成水花泡沫。
- 不需要新的外部 Noise/Normal Texture：第一版复用现有程序化 Triplanar/Wave Shader。
- Sticky Orb 第一版复用现有球形 Mesh/VFX 结构并换琥珀色 Material；法术 Icon 可暂用已提供的 `Status_Sticky.png`，无需阻塞功能实现。

## 手动调参入口

完成后，用户主要从以下位置调节：

1. `LiquidMaterialProfile_Sticky`
   - `Viscosity`：相对运动衰减，越大越黏、铺展越慢。
   - `Cohesion Strength`：团聚程度，越大越饱满，但过大会抖动/收缩。
   - `Maximum Cohesion Delta Speed`：限制 Cohesion 修正速度；过大易爆震，过小团聚不足。
   - `Rest Density / Particle Mass`：共同影响密度约束与体感，不能只凭“更重”单独拉高。
   - `Sleep Density Error Threshold`：稳定后进入 Sleeping 的容忍度。

2. `LiquidRenderProfile_Sticky`
   - `Target Voxel Size`：越小细节越多、GPU 成本越高。
   - `Iso Level`：改变等值面收缩/膨胀；过高可能缺边，过低可能臃肿并连接噪点。
   - `Crown Height Ratio/Falloff`：控制风格化凸起，不应拿来补偿错误 PBF 体积。
   - `Maximum Triangle Count`：容量保护，不是画质滑杆；Overflow 应先查范围/分辨率。

3. `M_ElementSticky_PBF`
   - Deep/Shallow/Fresnel Color、Alpha、Smoothness。
   - Wave Scale/Speed/Normal Strength。
   - Foam Distance/Strength/Alpha Boost。

4. `Status_Sticky`
   - `NaturalDecayPerSecond`：离场后恢复速度。
   - `MaxMoveSpeedSlowRatio`：环境固定减速上限和残留公式上限；当前为 0.4。
   - 不需要第二个“环境减速百分比”字段，避免两个真相来源。

5. Orb Prefab
   - `ProjectileStatusOnImpact.Amount`：Water 15 / Poison 10 / Sticky 20。
   - `ElementDepositOnImpact.TotalAmount/Radius/Falloff`：落点液体规模。

6. Reaction Profile/Bindings
   - `IgniteGoo.GooConsumePerSecond`、`FirePerGoo`、阈值与 Cooldown。
   - `DiluteGoo` 清除速率。
   - Material Pair → Reaction Id 映射。

## Rollback 与 Debug 顺序

出现问题时按层定位，不同时乱调 PBF、Iso Level 和 Material：

1. **无状态但能碰撞：** 查 `ProjectileImpactContext.Target` 与 `ProjectileStatusOnImpact`，不要先查 Renderer。
2. **有状态但无流体：** 查 Deposit Request、Simulation Route、Spawn Queue/Overflow 与 Remote Spawn Lease。
3. **有粒子但无表面：** 查 Renderer Target Material、Profile/Material/Compute 引用、Triangle Count、Indirect Args 和 Opaque Debug Flag。
4. **薄片/毛刺：** 先查 PBF 粒子空间分布、Voxel Size、Iso Level、Anisotropy/Crown；不要恢复 LOD。
5. **减速错误：** 查 Sticky Intensity、NaturalDecayHoldRemaining 与最终 MoveSpeedMultiplier，再查 Character 消费端。
6. **反应不守恒：** 查 Snapshot Version、Reservation、Batch Rejection 与 GPU Consume Count。
7. **卡顿：** 用 Profiler 区分 Solver、Readback、Reaction、Density、Marching Cubes、Draw；禁止仅凭画面猜测。
